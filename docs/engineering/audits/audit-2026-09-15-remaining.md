# softn.com: the parts the 15 September audits did not cover (read-only, 15 September 2026, HEAD 6cfe0eb)

Scope: `packages/@softn/components` (42 460 lines, 180 files, 92 component modules, 41 test files), `@softn/brand` (500 lines), `@softn/vite-plugin` (682 lines, one file), `scripts/*` (7 719 lines, 55 files), `.github/workflows/*` (verify, build, release) and `.github/scripts`, `e2e/` (1 860 lines, 11 specs), the Tauri side of `apps/softn-loader` (283 lines Rust) and `apps/softn-builder` (19 lines Rust; Studio has no desktop build), `docs/` (the kit: 4 scripts, 30 guides, 23 tests) and `examples/`. Method: `wc`/`grep`/`diff`, reading the risky paths in full, running nothing that writes. The tree was clean at the time (`git status` empty). Nothing modified.

## 1. Findings by severity

### High

**H1. Nothing verifies a push or a pull request.** `.github/workflows/build.yml:3-6` is `on: workflow_dispatch` only ("Automatic push/PR CI is temporarily paused while checks are run locally"). `verify.yml` is `workflow_call` only. So between tags no commit is typechecked, linted, tested, built for Tauri or audited by CI; the first time a commit is verified by a machine other than a laptop is when a `v*` tag is pushed (`release.yml:28-31`), and if it fails there, the tag already exists. Fix: `on: [push, pull_request]` for `verify` (it is already cheap: no Rust for the loader, no Playwright); keep the six-runner Tauri matrix on dispatch. Until then, the loader's Rust side is compiled by no workflow at all (`verify.yml:72-76` runs only `apps/softn-rust`), so a drift between the XDB pin in `.github/scripts/checkout-xdb.sh` and `xdb::tauri::*` command signatures in `apps/softn-loader/src-tauri/src/lib.rs:147-204` is caught only on a manual dispatch.

**H2. The documentation ships a guide that says it was not finished, and two dead links.** `docs/content/softn-docs.json`, page `single-app-runtime`, callout "This is a deployment overview: The source fetch for the detailed single-app guide failed during preparation. This page deliberately avoids claiming exact configuration fields or packaging flags" is published verbatim at `/docs/single-app-runtime/`. Its link (`:3253`) is `https://github.com/f2i-com/softn.com/blob/main/docs/SINGLE_APP_RUNTIME.md` and the language guide's (`:3026`) is `.../docs/ZIPP_LANGUAGES.md`; both files moved to `docs/engineering/` in 15fa946, so both 404. The build's validator (`docs/scripts/validate.mjs`) checks the schema, not the links. Fix: rewrite `single-app-runtime` from `docs/engineering/SINGLE_APP_RUNTIME.md` (the fields are `runtime.config.json`: `version`, `id`, `title`, `bundle`, `permissions`, `loadingText`, `theme`, `permissionMode`, `directory`, per `apps/softn-single/src/config.ts:15-24`), repoint the two links, and add a test in `docs/tests/docs.test.mjs` that every `github.com/f2i-com/softn.com/blob/main/<path>` link names a file in the checkout.

### Medium

**M1. Core carries a desktop feature the desktop never registered.** `packages/@softn/core/src/loader/useDynamicSoftN.ts:13-15,156,227,275,327` invokes `read_softn_file`, `watch_softn_files` and `stop_watching`; the loader's `invoke_handler` (`lib.rs:147-204`) registers `read_softn_bundle`, `read_cached_bundle`, `get_opened_file`, `set_window_icon` and the XDB commands, and Builder registers no custom command. The hook is a public export of `@softn/core` (`loader/index`) used by no app in the repository. Either implement the three commands (a directory watcher is the feature the hook describes) or mark the hook deprecated in the typings and remove it in the next minor; today a caller gets a rejected promise with Tauri's "command not found".

**M2. The desktop command surface trusts the whole webview.** Both apps set `withGlobalTauri: true` (`tauri.conf.json` `app`), and the loader needs it (`apps/softn-loader/src/App.tsx:49,179,292,399,407`). Any script that runs in the loader's webview may therefore call `read_softn_bundle` on **any** path ending in `.softn` (`lib.rs:37-50`: extension and existence are the only checks; the fs plugin's scope does not apply to a custom command), `export_database`, `import_database` and `get_db_path` (all registered, all used by the UI). Bundle logic runs in ZIPP and the renderer refuses raw HTML (`renderer/sanitize-html.ts`, `Icon.tsx:106` sanitises SVG), so today the only route is a bug in a component; but the design puts every bundle one XSS away from reading arbitrary `.softn` files and the database path. Fix: `read_softn_bundle` should accept only the path the app itself opened (`OpenedFile` state, or paths returned by the dialog plugin), and the three database commands should be gated behind a UI-initiated token the same way. `set_window_icon` (`lib.rs:76-96`) decodes untrusted PNG bytes from the bundle's `manifest.icon` with no dimension cap: `image::load_from_memory` on a 20 000 × 20 000 PNG allocates 1.6 GB and the loader dies on open. The JS side checks only the extension (`App.tsx:160-166`). Fix: read the IHDR first and refuse above, say, 1 024 px, or use `ImageReader::with_limits`.

**M3. The e2e gate runs nowhere.** `e2e/playwright.config.ts:12-13,22-26` calls the Chromium project "the per-commit gate (`npm run e2e`)" and names `.github/workflows/e2e-matrix.yml` for the matrix; neither exists in `.github/workflows/`, and `e2e/README.md:3-4` says to run the journeys by hand before a release. `release.yml` runs `smoke-site.mjs` (HTTP-level) but never Playwright. The eleven specs (26 `test(` calls) that prove a Builder → site hand-off, Studio → runtime, publish keys and the directory in a real browser are exactly what the unit suites cannot prove. Fix: an `e2e` job in `release.yml` after the site is packaged (`npx playwright install --with-deps chromium`, `SOFTN_E2E_URL` against the smoke root), and in `verify` when H1 is fixed.

**M4. Workflow actions are pinned by tag, not by commit.** `actions/checkout@v4` (×4), `actions/setup-node@v4` (×4), `actions/upload-artifact@v4` (×5), `actions/cache@v4`, `dtolnay/rust-toolchain@stable`, `tauri-apps/tauri-action@v0` — all mutable refs, on the release path that attaches archives with `contents: write`. FormLogic pins the same actions by SHA (`actions/checkout@3d3c42e5…`). Fix: SHA-pin with the version in a comment, as FormLogic does; `dependabot.yml` for `github-actions` keeps them fresh.

**M5. CI Node is 20; the PHP host's runtime wants 24.19.** `apps/softn-php/runtime/host-protocol.json:4` `minimumNode: 24.19.0`; every workflow uses `node-version: 20` (`verify.yml:37`, `build.yml:29,112`, `release.yml:122`). The new `apps/softn-php/tests/route-declarations.test.mjs` skips visibly under Node 20, so the release's "every test suite" excludes the one that runs the real runner. `package.json:82` `engines` says `^20.19.0 || >=22.12.0`, which does not match the runtime either. Fix: `node-version: 24` in the four places and `engines.node: ">=24.19.0"` (or document that the *host* needs 24 while the *build* needs 20+; either way the test must not skip in CI).

**M6. The release notes template is one version's changelog.** `.github/release-notes.md:1-12` is "What's new in 0.0.12" with five bullets about 0.0.12; `release.yml:262-264` substitutes only `RELEASE_TAG`, so v0.0.13's release page will say what was new in 0.0.12. The Downloads table there is the only place a visitor learns what the five archives are, and the archives themselves disagree on what the explainer is called: `DEPLOY.md` (site, `build-site.mjs:713`), `DEPLOYMENT.md` (single and php-serve, `package-single.mjs:18`, `package-single-php-serve.mjs:31`), `START-HERE.md` + `README-RUNTIME.md` (backend, `apps/softn-php/package.mjs:40,50`), `START-HERE.md` + `DEPLOYMENT-SERVE.md` (private, `:46`). Fix: split the template into a fixed part (the table, generated from one manifest of archives) and a per-tag part read from `CHANGELOG.md`'s section for the tag (fail the release if the section is missing); give every archive the same front door (`README.md` first, then the detailed guide), written by one function from the same manifest.

**M7. Four zip writers, three checksum writers.** `scripts/package-site.mjs` has its own dependency-free writer (store-vs-deflate by extension, zip64 refusal, read-back verification, `.sha256` sidecar); `scripts/package-single.mjs:20-45` uses fflate `zipSync` level 9 on everything (so `.br`/`.gz`/`.wasm` are deflated a second time, larger and slower) with its own read-back and sidecar; `scripts/package-single-php-serve.mjs` the same again; `apps/softn-php/package.mjs:6,79-82` fflate level 6 with a fourth verification and sidecar. Fix: `scripts/lib/archive.mjs` exporting `writeArchive(entries, out, {tag})` with package-site's rules, used by all four; the release workflow's `unzip -t` second opinion stays.

**M8. Chart palettes are hard-coded and off-theme.** `charts/AreaChart.tsx:43`, `BarChart.tsx:42`, `LineChart.tsx:49` each define `['#6366f1', '#ef4444', '#10b981', '#f59e0b', '#8b5cf6', '#ec4899']`; `GaugeChart.tsx:29` `#6366f1`; 66 of 92 component files carry a hex literal (top: `#6366f1` ×85, `#a1a1aa` ×80, `#ef4444` ×62) while the same files also use `var(--color-primary-…)` (×91) and `var(--color-gray-…)` (×115). A dark theme gets the right surfaces and the wrong series colours. Fix: one `chartPalette()` reading `--color-chart-1…6` with the literals as fallbacks, and a `style-egress`-style test that no component file introduces a new hex literal outside `theme/`.

### Low

**L1. The Vite plugin's file extension is the bundle's.** `packages/@softn/vite-plugin/src/index.ts:205-210` defaults `include` to `/\.softn$/` and parses the file as UI source; a `.softn` is a zip bundle everywhere else in the repository and the UI language files are `.ui`. Tests use `/src/view.softn` (`test/index.test.ts:15`). No app or example imports the plugin (only the docs mention it). `resolveId` (`:278-285`) returns `null` on both branches. Fix: default `include` to `/\.ui$/`, keep `.softn` as an opt-in with a warning, delete `resolveId`.

**L2. Scripts duplicate their plumbing.** `freePort`, `fail`, `opt`, `waitForServer` exist in both `scripts/serve-topology.mjs:46-149` and `scripts/smoke-site.mjs:33-108`; MIME tables in `package-site.mjs`, `serve-site.mjs` and `apps/softn-api/router.php`. The structure audit's `scripts/lib/` recommendation stands; this is the list.

**L3. `build-site.mjs:562-568` spawns `npm` with `shell: true` and an args array**, which Node 24 flags (`DEP0190`, visible in every site build). Fix: `execFileSync(process.execPath, [process.env.npm_execpath ?? require.resolve('npm/bin/npm-cli.js'), ...args])`, no shell.

**L4. Release builds carry devtools.** `apps/softn-loader/src-tauri/Cargo.toml:17` and `apps/softn-builder/src-tauri/Cargo.toml` enable the `devtools` cargo feature; `tauri.conf.json` only stops the window opening them (`devtools: false`), so Ctrl+Shift+I works in shipped binaries. Fix: `features = ["devtools"]` behind a `dev` cargo feature.

**L5. Desktop binaries are unsigned and unupdatable.** `tauri.conf.json` `certificateThumbprint: null`, no signing step in `build.yml`, no `tauri-plugin-updater`; the release notes say the desktop apps are not attached to releases, so this is documented, but a user building from the tag gets a SmartScreen warning on Windows. Note in `docs/engineering/`, or sign when the apps are released.

**L6. Loader CSP allows `connect-src wss:` to any host** (`tauri.conf.json` `security.csp`). Server sync (`apps/softn-loader/src/runtimeConfig.ts:13-17`) upgrades `https:` to `wss:` for a user-configured URL, and core's `egress-policy.ts` gates bundle traffic, so the breadth is by design; worth a comment beside the CSP so the next reader does not tighten it and break sync.

**L7. Components test holes.** No test names `NavItem` (1 031 lines), `SmartView` (529), `Pagination`; `Select` (797 lines, `role="combobox"` at `:732`) has two mentions but no keyboard-navigation test; 14 `console.*` calls in components (all guarded warnings). Accessibility is otherwise sound: every form control is a native `<input>`/`<button>` (`Checkbox.tsx:197`, `Switch.tsx:213`, `Radio.tsx:159`, `FileChooser.tsx:128`), `Tooltip` wires `aria-describedby`/`role="tooltip"` (`:533-559`).

**L8. Docs content accuracy (five guides read against the code).** `permissions`: the capability list omits `qr` (`bundle-format/src/capabilities.ts:33` has ten); the `net` shape (`enabled`, `allowed_hosts`) matches `egress-policy.ts`. `xdb-data`: `db.update(id, patch)`/`db.delete(id)` match `DBNamespace` (`script-runtime.ts:3565-3570`); `db.prune`/`db.clearCollection`/`db.get`/`db.hardDelete` are undocumented. `softn-app-format`: says "use a current example rather than guessing required fields" instead of naming them (`name`, `main`; `files` optional as of 96dac4c). `hosting`: build commands match `package.json`. `single-app-runtime`: H2. Two stray strings in the content: `http://localhost:1420,` and `softn.com.git\ncd` (inside code blocks; harmless but the link checker of H2 would catch the first).

**L9. `examples/`.** `Fieldnotes.softn` (committed at `apps/softn-site/public/examples/`) has `manifest.json` with `files` listing every entry and `permission.json` `{"permissions":{}}`: opens under the lenient rules, declares nothing, correct. `apps/softn-builder/src/utils/fieldnotesExample.test.ts:11-13` reads both the source and the bundle, so drift between `examples/fieldnotes/` and the committed bundle is caught. `aokie-workspace` and `formlogic-workspace` are `ui/` + `logic/` only (no manifest, no build, no test); they are workspace fixtures for the two integrations and should say so in a README each.

## 3. Test coverage holes

- Workflows: nothing runs on push/PR (H1); no e2e in any workflow (M3); the PHP host's runner test always skips in CI (M5).
- Docs: no link check (H2), no check that a guide's code sample matches a runtime type (L8).
- Tauri: no test of `read_softn_bundle`'s path rule or `set_window_icon`'s input bounds (M2); the loader crate is never `cargo build`-ed by CI (H1).
- Components: `NavItem`, `SmartView`, `Pagination`, `Select` keyboard (L7); no test that hex literals stay out of components (M8).
- Scripts: `package-single*.mjs` and `apps/softn-php/package.mjs` have no unit tests (package-site has `package-site.test.mjs`); a shared writer inherits its test.

## 4. What is sound (do not re-audit)

- `tauri-plugin-shell` `open` regex is anchored by the plugin (`scope.rs:96` wraps `^…$`), so Builder's `https://(softn\.com(/[^\s]*)?|github\.com/f2i-com/softn\.com)` cannot be prefixed. Builder's capabilities (`dialog:allow-open/save/ask`, `fs:allow-read-file/write-file/stat`, `shell:allow-open`) are dialog-scoped; the loader drops the shell plugin on purpose (`lib.rs:113`), and `read_cached_bundle` rejects separators and `..`.
- `.cargo/audit.toml` ignores two hickory-proto advisories with a written reason tied to the libp2p-mdns dependency; correct as stated.
- `release.yml` checks the tag against every manifest (`:93-117`), refuses a dirty tree via `BUILD-INFO.json`, stamps `SOURCE_DATE_EPOCH`, verifies the archive with the packager and with `unzip`, and smoke-tests the unpacked site through PHP; `checkout-xdb.sh` refuses a wrong commit.
- `fetch-demos.mjs` pins each demo by URL, size and SHA-256 and cuts off oversize downloads.
- `docs/scripts/render.mjs` escapes every string (`:1-2`), refuses unknown block types, and `build-docs.mjs` writes atomically, refuses symlinks and refuses source directories as output.
- `generate-third-party-notices.mjs` walks `package-lock.json` from the four browser apps only.
- `@softn/brand`: theme choice vs resolved theme kept apart (`theme.ts`), pre-paint script now asserted in every product-bar app, `ProductBar` external link has `rel="noreferrer"`.
- `e2e/.gitignore` keeps `test-results/` and `playwright-report/` out of the tree.
- Components: `sideEffects: false` holds (no module-level registration); heavy dependencies (`three`, the QR scanner) are behind `/scene3d`, `/media` entries with the eager barrel documented; `dangerouslySetInnerHTML` sites are sanitised (`Icon.tsx:106`) or self-generated (`Layout.tsx:51`, `CodeEditor.tsx:365`, `MarkdownEditor.tsx:408` documented).

## The eight most important findings

1. **H1** No workflow runs on push or pull request; the first machine verification of a commit is the release tag, and the loader's Rust is compiled by no workflow.
2. **H2** `/docs/single-app-runtime/` ships a "source fetch failed" placeholder, and two guide links point at files moved to `docs/engineering/`.
3. **M2** Any script in the loader webview can read any `.softn` on disk, export/import the database and learn its path; a bundle icon PNG with huge dimensions crashes the loader.
4. **M6** The release notes template is 0.0.12's changelog, and the five archives use five different names for their explainer.
5. **M3** The Playwright gate that the config calls "per-commit" runs in no workflow.
6. **M5** CI runs Node 20 while the PHP host runtime requires 24.19, so its runner test always skips.
7. **M1** `useDynamicSoftN` in core invokes three Tauri commands no app registers.
8. **M7/M8** Four zip writers and four hard-coded chart palettes; one shared archive writer and one token-backed palette.
