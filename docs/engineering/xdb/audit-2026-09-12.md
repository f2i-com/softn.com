# XDB integration and reliability review

Reviewed on 12 September 2026. Baseline: `fe6d06f` (10 March 2026).

## Current usage

XDB is an active dependency, despite the older commit date:

| Consumer | Integration |
| --- | --- |
| Softn desktop runtime | Direct Rust `xdb` path dependency; registers the Tauri commands and opens a SQLite database for each bundle. |
| Softn Rust server | Direct Rust `xdb` dependency with Tauri disabled; collection API, database bridge and synchronized records use it. Server sync batches writes through `with_transaction`. |
| Softn browser, Studio and Builder | Softn's own TypeScript XDB adapter. It uses browser storage and preview scopes, or delegates to this crate in the native host. |
| FormLogic and Aokie | Their Softn apps share the app format and backend bridge. Hosted business data and native Aokie call records also have separate SQLite implementations. They do not directly consume `@xdb/react`. |
| OAIY and ZIPP | No direct dependency on this repository. Softn supplies ZIPP's database bridge. |
| XDB demo | Uses both this Rust crate and `@xdb/react`. |

The [README](../README.md#where-xdb-is-used) links to the consumers. Changes to Softn's browser adapter do not necessarily produce commits in XDB.

## Changes made

### Durable storage and restore

- Replaced raw file copies with SQLite's backup API. Exports and restores now include committed pages in WAL while a source database remains open.
- Restore validation checks SQLite structure, record JSON and saved CRDT documents before replacing the current database. Missing, unrelated or damaged files leave the target usable.
- Prevented import/export to the same database and transfers inside an unfinished transaction.
- Preserved a previous backup when that backup is itself selected as the import source.
- Reload retains normal database initialization. Size statistics count the logical snapshot, including WAL pages.

### Transactions and data consistency

- Nested operations use savepoints. Errors, failed commits and unwinding callbacks invalidate cached Yrs documents after SQLite rollback, preventing uncommitted records from appearing in later sync state.
- A caught inner transaction failure rolls back that inner operation without losing successful outer writes.
- Deleted record metadata stays consistent between SQLite and its replicated tombstone.
- Damaged record JSON and saved CRDT bytes produce errors instead of being silently replaced with null or empty documents.

### Native integration

- The default network and Tauri commands share one database. Explicit custom default paths are respected by both.
- Named apps no longer publish records through the default protocol, which has no app identifier. Requests for unsupported native sync return a clear error.
- Scoped local mutation and import events allow React views to refresh when another view changes data.
- Peer status follows actual connections, including multiple connections and expired discovery addresses. Stopped network tasks no longer report as running.
- Message checks use the signed original author rather than the last relay. Failed remote writes do not emit successful sync notifications.
- Offline publish attempts are logged as expected offline state rather than database failures.

### React package and maintenance

- Added optional app IDs to database hooks.
- Prevented delayed queries and mutations from updating a newly selected app or collection.
- Preserved optimistic edits across refreshes and concurrent failures; tracked concurrent mutations independently.
- Fixed stale event callbacks, delayed listener cleanup and listener failures.
- Prevented overlapping polling; retained the newest response when requests finish out of order.
- Corrected filtered totals before pagination and sorting by record metadata.
- Added a Windows Common Controls manifest for the native test executable.
- Updated compatible npm tooling dependencies. A successful registry audit reported zero npm advisories after resolving the initial eight. Rust dependency findings are tracked separately below.
- Updated documentation and Node requirements, and ignored SQLite WAL/SHM and generated backup files.

## Remaining design work

> **Follow-up (14 September 2026):** the first three items below were implemented for the ecosystem review (tickets XD-01, XD-02, XD-03, SN-01); the current contract is [networking-and-restore-policy.md](networking-and-restore-policy.md). Peer authentication/authorization for a successor protocol, sanitized-id collisions and whole-record conflict granularity remain open as described.

- Native peer sync still needs explicit app identity, authorization and reconnect reconciliation before it can support named hosted apps. It currently uses one default namespace on the local network. Transport signatures do not provide user authorization.
- Offline deltas are not queued. Default peers need explicit synchronization after reconnect; a queued publish is not an acknowledgement of remote persistence.
- `clear_collection` resets local SQLite and CRDT state. It is not a replicated deletion. Imports and resets can be repopulated from peers; synchronized deletion should use record tombstones.
- Sanitized app IDs can collide. Hosts should continue generating stable safe IDs (the Softn runtime uses bundle digests). Changing the path mapping requires a migration strategy.
- Same-record concurrent edits resolve at whole-record granularity, not per field.
- The standalone React package is demo-only among the reviewed consumers. Changes needed for Softn's browser XDB implementation belong in the Softn repository.

No live data migration, native sync protocol redesign or operating service restart was performed. Linux and macOS builds were not run on this Windows host.
