# Engineering, product and content audit, 6 September 2026: findings and what changed

A second external review — of the current source, selected demos, the
site's launch and data paths, the PHP directory, the runtime helpers and the
release workflows — produced twelve ranked findings on 6 September 2026, the
day after the first ([`audit-2026-09.md`](audit-2026-09.md)). This is the
record of each and its status in the tree.

The review's framing, again worth keeping: keep the architecture and
tighten its contracts. Its theme was consistency across the run / inspect /
download / remix loop — the right bundle opens, its identity is respected,
saves survive a deliberate update, permission information is accurate, and
release checks cover the bytes actually shipped. Most of what follows is one
rule applied where a parallel path had its own.

## Implemented

| ID | Finding | Where |
|---|---|---|
| A01 | A pre-identity cache record (keyed by manifest name) was adopted by the first bundle to arrive under that name, whatever its bytes, and its stored data moved with it. | `apps/softn-web/src/lib/appCache.ts`: the cached bytes are hashed and only the same bytes adopt the record. Different bytes get a record of their own with no data and no grants, and the legacy record is upgraded to its own digest identity so the launcher's explicit "bring my data forward" flow can relate the two. Hashing happens before the IndexedDB transaction opens; the record is re-read and compared inside it before anything is written. The data move copies first and removes the source only when every key is in place, so an interrupted migration leaves the original where it was. Tests: `apps/softn-web/test/appIdentity.test.ts`. |
| A02 | Open-tab reuse keyed on the app name: an update, or an unrelated bundle called Notes, activated the tab already running under that name. | `apps/softn-web/src/lib/tabIdentity.ts`: a running tab is found by the bundle's digest; a placeholder is claimed by the id its creator was given (`processBundleData` takes it as a parameter), never by what it is called; a bundle opened from a URL is recognised by its directory slug or the address, not its name. Two same-name apps coexist as two tabs, and the launcher's running list appends the version where names collide. Back/forward prefers the tab being looked at when two share an address. Tests: `apps/softn-web/test/tabIdentity.test.ts`. |
| A03 | `deepEqual` decided what kind of value it was comparing from the first operand alone: `{a: undefined}` equalled `{b: undefined}`, two DataViews with different bytes compared equal, `{}` equalled `new Set([1])` one way round. | `packages/@softn/core/src/runtime/vm-state.ts`: both operands are classified and must agree; objects check own-key membership, not just count; DataViews and typed-array subviews compare over their own byte range. Every reproduced case, the symmetry cases, nested undefined keys, empty array versus object, subviews, NaN and representative round trips: `packages/@softn/core/test/vm-state-deep-equal.test.ts`. |
| A04 | Play navigated in the run-count request's `.finally()`; a slow or blocked `/runs` endpoint was a Play button that did nothing. | `apps/softn-site/src/lib/launch.ts` starts the count and navigates at once; `recordRun` returns nothing awaitable, uses `keepalive` and a ten-second timeout. Tests: `apps/softn-site/test/launch.test.ts`. A launch and a run are now counted apart: the site's Play sends `{stage: "launch"}` (an `apps.launches` column), and the runtime sends `{stage: "open"}` when the app reports itself ready — once per tab, in `announceReady` — which is what the pages show as runs. Before, a Play from the directory was counted twice: once by the click, once when the bundle parsed. |
| A05 | A failed categories request set a global "API down" flag that made every page skip its app-list request. | `apps/softn-site/src/App.tsx` keeps a categories status with an in-place retry; `HomePage`, `DirectoryPage` and `PublishPage` ask for their lists regardless, render cards without category labels, and show a soft notice for the categories alone. The list has its own retry on both pages. The front page remembers the last featured shelf this browser saw and shows it, marked with its date, when the live request fails. Tests: `apps/softn-site/test/directory-status.test.tsx`; the site now has a vitest suite (`npm test -w @softn/site`). |
| A06 | The runtime enforced ten capabilities; the directory's PHP enumerated nine (no `accel`) and the site's label map nine, so an app asking for host acceleration was listed as asking for nothing. Unknown or malformed declarations silently became an empty display. | `packages/@softn/core/src/runtime/capabilities.ts` is the versioned schema: the list, its words, `inspectDeclaration`. The web loader re-exports it; `apps/softn-api/lib/bundle.php` and `apps/softn-site/src/lib/capabilities.ts` carry copies that `apps/softn-web/test/capability-schema.test.ts` compares against it, together with the consent dialog's descriptions. The PHP refuses a declaration at publication when it names an unknown capability, a non-object entry or a non-boolean `enabled`, with the names in the message (`apps/softn-api/test/api.test.mjs`). The app page now says "What it asks for" and that the runtime grants each capability only when allowed, on a device that has it. |
| A07 | The release workflow packaged a tag without running the typecheck / lint / test suite on that commit. | `.github/workflows/verify.yml` is a reusable workflow holding the verification steps; `build.yml` calls it on push and PR, and `release.yml` calls it with the exact tag ref and packages only after it passes. The packaged archive is then unpacked and served through PHP with the API's router — `scripts/smoke-site.mjs` — and asked for the pages, the nested SPA routes, the API (health, the seeded list, one app, its bundle, the share page, a JSON 404), a demo bundle and a hashed asset, checking status, content type and the cross-origin isolation headers on each, and that `/data/` and `/api/lib/` are refused. The script runs locally against `dist/` too, without writing into it. |
| A08 | Copying saves between builds wrote keys one by one and returned a count; a quota failure part way left the destination mixed and the update opened anyway. | `transferStorageKeys` in `appCache.ts` records every write and undoes them all on failure, so the destination is exactly as it was; it returns `{ok, copied, total, skipped, error}`. `handleAdoptData` in `apps/softn-web/src/App.tsx` shows the failure and does not open the update. The same primitive does the legacy-record migrations. Tests: `appIdentity.test.ts` (failure on the second write, destination collisions, move-that-fails-is-a-copy-that-failed). |
| A09 | Scene3D's procedural textures lived in a module-level Map with no bound or eviction. | `packages/@softn/components/src/threed/textureCache.ts`: a reference-counted cache with an idle budget. Materials acquire a texture and hand it back on disposal (`disposeMaterial`), so a texture a live material holds is never disposed under it — the old disposal path disposed the shared texture out from under other meshes — and idle textures are kept for reuse up to the budget, least recently used first out. `proceduralTextureCacheStats()` is exported for a development inspector. Tests: `packages/@softn/components/test/texture-cache.test.ts`, including repeated open/close settling within the bound. |
| A10 | Per-app server storage is public shared data, with no way to say otherwise per collection, and nothing said so plainly. | Collection policies, declared in `permission.json` under `storage.collections` and fixed at publication: `public` (the default), `append-only`, `owner-write`, `private` and `publisher` (the review's server-only), with `*` for a default. `apps/softn-api/lib/storage.php` enforces them per operation; ownership is a visitor token the runtime mints once per browser (`packages/@softn/core/src/runtime/visitor-token.ts`, sent as `X-Visitor-Token`) and the server keeps only a salted, app-bound hash. Records carry `mine`. The schema (`capabilities.ts`, version 2) validates the declaration in TypeScript and the PHP refuses an unknown policy at publication by name; the app page lists each collection's policy. The README says what each policy is for, that a score nobody can alter is not a score that was earned, and that an edit key must never be embedded. Tests: `apps/softn-api/test/api.test.mjs` (two visitors and the publisher against every policy), `packages/@softn/core/test/capabilities.test.ts`, the drift test. |
| A11 | Texas Hold'em replicates hole cards and the deck through shared state; the trusted-peer label lived on a home-page showcase that no longer exists. | Two things. The peer table is labelled on the app itself as a table for friends who trust each other. And there is now an **online table with an authority**: `server/rules.logic` is the game as a pure state machine (blinds by last big blind, min-raise by last full raise, short all-ins that do not reopen action, side pots by contribution level, odd chips left of the dealer, timeouts), and `server/authority.logic` is the table service that softn-server runs from the bundle's own `manifest.server` routes: rooms with codes, seat tickets, a revision on every view, idempotent actions journalled by id, stale-view and out-of-turn refusals with the current revision, presence, reconnect, leave, and projections — the public table for everyone, one seat's own cards for its ticket, never the deck. The client's lobby offers "Create online table" / "Join"; the table page renders the server's view through the same globals, with card backs for hands it is not sent. Tests: `apps/demo/scripts/test-texasholdem-authority.cjs` (the audit's acceptance matrix plus chip conservation, no duplicate cards and determinism over 190 seeded hands), `test-texasholdem-authority-client.cjs` (two clients, one authority, in-process) and `test-texasholdem-authority-http.cjs` (the same over HTTP on a built softn-server). |
| A12 | Identity was SHA-256 truncated to sixteen hex characters, with a non-cryptographic fallback that looked the same. | `computeAppOrigin` keeps the whole digest; `abbreviateOrigin` is for labels. Records keyed by the short digest are recognised by hashing their bytes and carry their data and grants across. The insecure-context fallback is prefixed `insecure-` and `recordPermissionGrant` refuses to persist a grant under it, so an identity other bytes could be made to share never carries durable trust; the launcher warns once per open. Tests: `appIdentity.test.ts`. |

softn-server gained `db.updateIf(id, patch, field, expected)`, a conditional
write under the store's writer lock, so the poker authority commits a room
only if its write stamp is still the one it read and answers `RETRY`
otherwise; the HTTP test races six actions and six joins on one room across
four workers. The server also stopped requiring a bundle's display name to be
an identifier when the manifest has an `id` to name the data directory by.

The smoke test earned its place on its first run: the local PHP router
(`apps/softn-api/router.php`, the stand-in for the deployed `.htaccess`)
served the runtime's nested routes — `/web/app/Pocket`, the document a
worker-mode app runs in — without the cross-origin isolation headers, so a
preview through it had no `SharedArrayBuffer` where the deployed site does.
The router now sends them from every branch it answers from.

Compatibility notes:

- `permission.json` may now carry `storage.collections`, a policy per
  collection. Bundles without it behave as before: every collection is
  `public`. The schema version is 2.
- The runtime sends `X-Visitor-Token` with storage requests, a random
  per-browser string kept in local storage under `softn.storage.visitor`.
  Existing records have no owner; under `owner-write` only the edit key can
  change them, and under `private` they are visible to nobody.
- Storage records now carry `mine`. `runs` on an app now counts the runtime
  reporting the app up; `launches` counts Play on the site.

- A bundle whose `permission.json` names a capability the runtime does not
  have, or whose entries are not `{ "enabled": <boolean>, ... }` objects, is
  now refused at publication with the names in the message. Every demo
  bundle already conforms.
- Cached apps opened again are re-keyed from the sixteen-character digest to
  the full one on first open; data and grants come across. Nothing is
  deleted. A pre-identity (name-keyed) record is adopted only by its own
  bytes; a different bundle with the same name appears beside it in the
  launcher, and the older build's records can be brought forward with the
  existing button.
- The runtime's `?open=` and `/app/<slug>` flows recognise an already-open
  bundle by its slug or address rather than its name. Two bundles with one
  name open as two tabs.

## Not implemented

| ID | Finding | Status |
|---|---|---|
| A11 (deployment) | Running the poker authority for the public site. | The authority is a softn-server process the PHP-hosted site does not include. `docs/hosting-the-poker-authority.md` is the recipe: run it, proxy a path of the site to it (same origin, no CORS), republish the bundle with the host in its `net` grant; the deploy guide in every release points there. The client remembers the last table server used. Hosting it for softn.com is an operations decision, not code. |
| RFC | The general room facade (`softn.net.rooms`), transports, membership across apps, the companion QR journey, public matchmaking. | Proposal only. The poker authority is one app's server logic over plain `softn.net.fetch`, which is the RFC's "authenticated server actor" for one service, not the facade. |

The review's sections on architecture (one identity model at every
boundary, generated contracts, a host/app responsibility split, an
inspectable runtime), the benchmark suite built from the existing apps, the
website and publisher experience, the fixture matrix, the proposed apps and
the content strategy are direction, not findings, and are not recorded here
as done or not done. Of them, the capability schema is the first generated
contract, `proceduralTextureCacheStats` the first inspector hook, and the
smoke test the first packaged-artifact acceptance check.
