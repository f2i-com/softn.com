# Changelog

One section per release tag, newest first. The release workflow takes the
section for the tag being released and puts it at the top of the release
notes, above the downloads table; it refuses to package a tag that has no
section here. Write the section before tagging. Headings are the tag
(`## v1.2.3`); anything after the tag on the heading line is ignored.

## Unreleased

- The `.ui` language reads the expressions a JavaScript author writes first. Arrows without parentheses (`tasks.filter(t => t.done)`), spread in a list, an argument list and an object (`[...done, item]`, `Math.max(...scores)`, `{ ...base, color: "red" }`), `count++` and `--count`, `**`, `in`, `instanceof`, `undefined`, hexadecimal numbers, numeric object keys, and `new` for `Date`, `Array`, `Map` and `Set` (nothing else is constructed). Several of these were not refused before but read as something else with nothing said: `count++` parsed as `count + +undefined` and set the count to NaN, `2 ** 8` as `2 * undefined * 8`, and `{/* a comment */}` as divisions of nothing that rendered "NaN"; a comment inside braces now renders nothing. `Map`, `Set` and `Object.keys`/`values`/`entries` join the globals a template can name; `Object` is those three read-only functions and no more.
- A variable can be called `data`, `style`, `from`, `end`, `empty`, `prop`, `slot`, `template`, `component` or `collection`. The lexer types those words as keywords because markup uses them, and applied that inside expressions too: `{data.title}` was "Unexpected token data", `#each (prop in props)` failed on its own loop variable, and `#if (end > start)` left the condition at `end`. JavaScript's own reserved words stay reserved.
- `#else if (…)` is `#elseif (…)`. It used to render the text "if (b)" and merge the two branches.
- Event modifiers: `@submit.prevent={save}`, `@click.stop`, `@click.self`, a key (`@keydown.enter`, `.escape`, `.space`, `.tab`, the arrows, `.backspace`, `.delete`) and a held key (`@keydown.ctrl.enter`). A script never receives the live event, so until now a handler could not cancel a default except through an arrow in the template that inspected the event. An unknown modifier is a diagnostic; whatever `:bind` does on the same event is never filtered.
- `style:property={value}` sets one style property beside the rest of `style`, as `class:name={condition}` does for one class, including custom properties (`style:--accent={colour}`); a remote `url()` written that way is withheld by the same rule as a style object. Names after the colon are read whole: `class:is-active={on}` was the class "is" and a stray attribute `active`.
- An operator with nothing on its left (`{/a+/.test(s)}`, `{* 2}`) and a `{…}` among a tag's attributes (`<Button {...rest}>`, which became a boolean attribute `rest`) are diagnostics rather than silent misreadings. `PARSER_VERSION` is 5.
- Builder writes all of the above back as it reads it (its expression printer knows the new operators and their precedence, and keeps an event's modifiers), and Studio's agent is taught the forms and no longer told to avoid them; its name check takes an arrow's bare parameter as a local and reads what a spread, an update and a construction name.
- Eight more components, 98 in all. `Stat` (one figure, its label and how it moved, coloured by whether the move is good news), `Steps` (progress through a sequence; buttons when bound), `Timeline` (a list of things that happened, from state), `Kbd` (a key or shortcut), and three controls that hold one value and hand back the value itself: `SegmentedControl` (one of a few options, side by side), `NumberInput` (a number or `null`, never its text; typed text is left alone until it is a number and settled into range on leaving) and `Rating` (stars as a radio group; read-only it is announced as "3 out of 5"). `Skeleton` was exported and documented but never registered, so `<Skeleton>` in a page was an unknown component; it is a tag now. All are in the minimal set, the Builder palette and Studio's component index, use theme tokens only, and say in words what their marks say: a trend's direction, a completed step, the score.
- Layout, a visible change for existing apps: `<Stack padding>` has its top padding and `<Grid>` has its gap. Since the first release the components set a shorthand and then its longhand as `undefined` (`padding` then `paddingTop`, `gap` then `columnGap` and `rowGap`); React writes an undefined style as an empty one, which takes that part back out of the shorthand, so in a browser every padded Stack had nothing above its content and a Grid never had a gap unless both longhands were passed. A bordered `Accordion` was open at the top and a separated one neither closed nor rounded, and a `DatePicker` with no date lost its right padding, for the same reason. jsdom and server rendering skip an undefined value rather than clearing it, so no test saw it; the rule is now checked in the source (`npm run audit:styles -w @softn/components`, held by a test). Pages laid out by eye around the missing space will have more of it.
- `Rating` and `SegmentedControl` follow an app that clears its bound state (they kept showing the last choice), `SegmentedControl` keeps its own width inside a column, an empty star is a grey that can be seen, and `<App>` publishes `--color-text-disabled`, which eight components read.
- A write to state in the body of a page is not made. `{count++}` (or an assignment, or an arrow the drawing itself calls) ran on every drawing and caused the next one, which React ends by taking the document down; it is now worth its value, changes nothing and says so once. Handlers are unaffected, and a callback prop written as an assignment (`onClose={open = false}`) is the action it reads as rather than an assignment made while drawing.
- An operator with nothing after it is a diagnostic too: `{total + }`, `{ok ? "yes" : }`, `{user.}`, `{() => }` and `#if (count > )` each parsed as a complete expression around a stand-in `undefined`.
- PHP backend host: a photo upload is turned the way its EXIF orientation says. GD ignores the tag and the copy handed to the handler has no EXIF, so a portrait photo from a phone arrived lying on its side; the Rust host already turned it. JPEG only, which is what cameras write. `softn.config.photos` is the host's answer (the capability granted and GD loaded), where an app's own `config.app.photos` passed straight through.
- PHP backend host: a body with a number outside the range of a double (`{"n":1e999}`) is answered 400 `invalid_request`, as the Rust host answers it, before a runner is started. PHP decoded it to `INF`, which cannot be written back as JSON, so the request failed on its way to the runner and the client was told 503 "please retry" for a body no retry could mend.
- Directory, app storage: an empty object an app stores comes back as an object. PHP read `{}` and `[]` as the same empty array and returned both as `[]`, in a record's fields and in a key-value value; an app that read its `{}` back as a list and set a field on it then saved `[]` again, because JSON drops a named property of an array, so a setting that started from an empty object was never kept. Values already stored as `[]` stay as they are.
- Rust backend host: `db.query(collection, filter)` in a server script filters, where the filter was dropped and every record of the collection came back (it filters what the host reads for a query, which stops at 10,000 records of a collection, as an unfiltered query does). `softn.config` carries the app's own settings (the manifest's `config.app`), as the PHP host's does, under the operator's `development` and `photos`, which an app key of the same name cannot replace; it is frozen all the way down, since it outlives the request. Every response carries `X-Content-Type-Options: nosniff`, which the PHP host's `.htaccess` already sent.
- `db.query(collection, filter)` filters in the worker too. Logic a bundle runs in the worker (`config.execution: "worker"`) got every record of the collection back whatever the filter said; it now gets the records whose data has every field of the filter, the rule the main thread always applied.
- Rust backend host, sync: a `create` the client sends again (it re-sends every op until acknowledged, and an acknowledgement can be lost after the commit) no longer replaces the record with its first payload. It wrote over whatever another client had changed since and brought a deleted record back; it is now acknowledged without being written, broadcast or handed to the after-sync hooks. A per-op `onBeforeSync` that returns `{ data: undefined }` keeps the record's payload instead of replacing it with JSON null, as the batch hook already did, and what an after-sync hook throws is logged rather than discarded.
- Rust backend host: an archive entry is read no further than the size limit whatever size it declares (a `.softn` whose entry claimed a kilobyte could inflate to anything in memory while loading), and in `serve-multi` a bundle is checked against the reserved and already-loaded tenant ids before anything is opened: a bundle declaring another tenant's id used to open that tenant's database and run its own start-up code against it before being dropped as a duplicate.
- Directory: `backup.php restore --force` no longer empties the data folder it is restoring into. It cleared the destination, kept `README.txt`, then stopped at `README.txt` as "appeared while restoring", because every export carries the `README.txt` and `.htaccess` the site ships in `data/`: the live catalogue was gone, the restore had not happened, and the staged copy the message named had been removed. Restored files are now moved in first, what was there is set aside and deleted only when every file is in place (and put back if a step fails), and the shipped files and lock files do not make a fresh deployment's folder "not empty".
- Directory: a publisher's new version cannot change a collection's storage policy. The policy in force was read from the newest version's declaration, so an app published with `notes: private` could be given a version declaring `notes: public` and every visitor's private records became readable by anyone. A version may re-spell the declaration; one that changes what a collection comes to is refused with the collections named. An app without storage may add it, and the operator may change anything.
- Directory: a publish or remix whose picture is refused creates nothing (it answered 400 after the app was listed, with an edit key nobody was sent, and the retry published a second one); `?v=`, `?v=latest` and `?v=0` are no longer served as version 1 under a pinned version's one-day cache (empty is the latest, anything else that is not a version number is 400); the demo sync leaves alone an app a visitor published under a name a later demo uses, where it replaced their bundle and description; the storage quota is counted in bytes on both sides (text that is not ASCII was admitted at three to four times the quota); and a storage file that is not a database answers 503 for storage and no longer takes the app's page down with a 500.
- PHP backend host, a change in behaviour: a host call that fails rolls the request back even when the handler catches the failure and answers. It used to commit what the handler had written before the failed call (a transfer that credited one account, failed to debit the other and answered 400 left the credit in the database). Such a request now answers `500 host_error`, as on the Rust host, unless the handler returns `rollback:true` with its own answer. A handler that relies on catching a failed statement and carrying on needs that flag, or a query that checks first.
- PHP backend host: `config.server.requestsPerMinute` is read (it was 120 whatever the manifest said; 0 turns the limit off); the lock wait is set before the switch to WAL, so a request opening the database while another closes it waits instead of answering `database_busy` at once; `softn.time.age(date)` without a zone is UTC rather than a 500; the runner's deadline ends the process with a signal, since an exit waited for a worker inside a statement that never finishes and the process outlived the deadline holding its slot and the write lock; the slot lock is not inherited by the runner; and `setup.php` on an archive with no app installed says so instead of dying with a TypeError.
- PHP backend host: a client past its rate limit is refused before anything is started. The runner counted, so a 429 cost a worker slot, a Node process and (on a photo route) the decode, as much as the request it refused, and a client over its limit could keep every slot busy. The runner now notes a refused bucket in `private/limited/` and PHP answers the rest of that minute's requests from it alone, with `Retry-After`.
- PHP backend host: what fails is written to PHP's error log, one line naming the handler or startup stage and the reason (no stack, bind values, keys or paths), where a failing handler, a failing statement and a Node that would not start all left no trace. A `runner_unavailable` answer names the step that failed as `diagnostic`. The README says what the log can contain.
- PHP backend host: a host call carries 2 MiB of arguments, as on the Rust host (it was 1 MB), and a non-ASCII body reaches the handler whole: escaped on its way to the runner, 2 MiB of two-byte characters was refused as too large, and unescaped text fed to the runner lost a character at each chunk boundary.
- Rust backend host: a client that stops reading can no longer hold the host open. A response (or a sync message) the client takes no byte of for 30 seconds is dropped, where a write had no deadline at all; 768 connections are served at once and the rest wait; shutdown gives requests in flight 40 seconds and then exits, where one unfinished connection kept the process alive for ever. A sync peer that stopped reading kept its connection slot and its queued messages.
- Rust backend host: the worker pool survives stalls. The limit of eight abandoned workers was a count for the life of the process, and past it a wedged worker was dropped from the pool with no replacement, down to none. It is now eight at once, given back when an abandoned thread finishes, and a worker that cannot be replaced stays in the pool.
- Rust backend host: photo decodes are bounded across the host (503 `database_busy` past it) instead of by a minute's rate allowance at once; API answers carry `Cache-Control: no-store` and the JSON-only `Content-Security-Policy`, `req.headers.authorization` and `idempotency-key` are always present on API v1, and an answer may be 3 MiB, all as on the PHP host; data a sync before-hook hands back must be an object of a size a client may send, or the op is not applied.
- Rust backend host, multi-tenant: when two bundles claim one tenant id, the one that served that tenant's data before is loaded (recorded in a `.bundle` file in its data directory) and the other is refused before it is unpacked, where the winner was whichever the directory listed first. Renaming or moving a bundle is unaffected.
- Directory: the demo sync compares a demo with version 1, the one it wrote. Compared with the latest, a seeded demo whose owner had published a version 2 never matched: every request replaced `v1.softn`, moved the app's dates and wrote version 1's capabilities over the app, so a version 2 that added storage was played without it. Demos and screenshots are hashed when they change, not on every request.
- Directory: a name that spells no slug no longer means `app`. A visitor's category called "App" became the category of every app published with none, suggestions in other scripts shared one category, and an address in another script was the app whose slug is `app`. Thumbnails and icons answer 304, an app keeps ninety days of daily run counts instead of every day, and an export leaves out the rate-limit counters and the remaining lock files.
- Directory, app storage: in a `private` collection a record id is the visitor's own. Ids were one namespace per collection, so an app keeping each visitor's settings under a fixed id worked for the first visitor only: the next one's `set` answered 404, their `insert` 409, which also told them someone else had a record there. Records added before this, under bare ids, stay where they are and stay their owner's. Removing an id you hold nothing under now answers `{removed: 0}` whether or not anyone else uses it.
- Directory: a storage request, and the storage summary on an app's page, no longer hold the directory-wide catalogue lock while they work in the app's own database. A query over a large store or a write waiting on SQLite held the one lock every request needs, so a single visitor inside the storage rate limit could keep the whole directory, listings included, waiting. An export and the removal of an app still find its store quiet: they take a new `storage.lock` that requests in a store hold shared.
- Server sync: a collection past 10,000 records is pulled whole. The Rust host sent its oldest 10,000 and nothing more, so a new device never received the newest records and nothing said so. A full pull is now paged: the host says where the next page begins (`more` on `sync_state`) and the runtime asks for it (`cursor` on `sync_pull`), until a page is not full. Both fields are optional, so older clients and hosts behave as they did.
- Rust backend host, sync: a push is acknowledged and broadcast as soon as its ops are stored, before `onAfterSync` runs. The answer used to wait for the after-hooks, and a push whose hooks took long was told "timed out" and sent again while the first attempt committed. The per-op `onBeforeSync` stops taking ops of one push after five seconds and the client re-sends the rest.
- Rust backend host: `db.query(collection, filter)` applies the filter in the store's query, so the 10,000-record limit counts what matches. Filtered by the script after the read, a match past the oldest 10,000 records of a collection was never found.
- Rust backend host, sync: a push saves each collection's CRDT document once. The document is as large as the collection and was written again for every op of a push, under the store's one writer lock, so a large push held every other write on the host and could outlast its own connection. This needs the xdb revision the build now pins (`with_batch`, xdb.org `c993b5e`): xdb.org has to be pushed before this builds in CI.
- `PixelGrid` fits the width it is given. A board of `cols * cellSize` pixels in a narrower column was cut off by what held it (Blockfall showed about seven of its ten columns on a phone); it is now drawn whole at that width, every cell and the overlay's lettering smaller by the same amount, and at its own size wherever there is room.
- No built-in component throws for a prop that is `null`, which is what a page gives it until its data arrives; a default parameter only stood in for `undefined`. Each of the 98 registered components is mounted bare, with every prop null, and with every choice mistyped (`test/missing-props.test.tsx`).
- A `size` or `variant` that is not one of the component's choices (`<Button variant="primay">`, `size={null}`) is the default one. It used to throw and leave the renderer's error box where the component belonged (Button, Input, TextArea, Select, Checkbox, Radio, Switch, Slider, ColorPicker, Tabs, Alert, Toast, EmptyState, Tooltip, Avatar, SmartStats).
- `DataGrid` without `columns` shows a column for each field of its rows, where it used to throw; a column may be only its field's name (`columns={["name", "team"]}`).
- `SmartForm` without `fields` is an empty form, where it used to throw. A stray comma in `fields="name, , email"` is not a field (it was an input with no name), and a field in a list may be its spec as text.
- Chart `padding` may name some sides (`padding={{ left: 80 }}`) or be one number; a side that is not given keeps the chart's own. Either used to leave the plot NaN wide and empty. A `null` padding or formatter is the chart's own.
- `TileMap` given only its `layers` is the size they cover. Without `mapWidth` and `mapHeight` its canvas was sized NaN and the map was cut off at 300 by 150.
- `Scene3D` in a browser that gives no WebGL says so in its own box, where it used to throw into the page's error box.
- `SmartStats` reads `columns="3"` as three; it read any string as the default four.
- `TextArea` is emptied when the value it is bound to goes back to `null`. It used to keep the old text on screen after a form was reset, while the state behind it was empty.
- `DatePicker` takes a timestamp (milliseconds, as `Date.now()` gives it) for `value`, `defaultValue`, `min` and `max`, where a number used to throw.
- A list with a `null` in it (a deleted record) no longer takes `Table`, `DataGrid`, `SmartGrid`, `SmartList`, `SmartTimeline` or `SmartCards` to the error box: a hole is not a row.
- `SmartStats` draws `stats="Users"` (a spec whose figure is not typed yet) and shows a dash for a figure that is undefined, where both used to throw. `SmartGrid` leaves the empty name in `columns="name,,team"` out.
- `Avatar` draws no presence dot for a `status` that is `null` or not one it knows (it drew an empty ring and read out "null"), and takes a number for `name`.
- **Security:** a URL prop that is not text is no longer passed on. `<a href={["javascript:alert(1)"]}>` reached the page with the script URL intact, because the URL check read only strings and React writes a list out as its entries joined; the same list under `src`, `srcset`, `poster`, `ping` or in an inline `style` fetched from any host before consent and without `net`. Under a URL name, text is judged, a number is its digits, and anything else is removed, on raw elements and at any depth in a component's props.
- **Security:** a URL nested more than four levels down in a component's items is judged. The scrub used to stop at a fixed depth and hand on what lay below unchecked; a value that refers back to itself is now cut where it comes round instead.
- `Image`, `Avatar`, `Sprite` and `TileMap` given a `src` that is not text draw without it, where the URL check threw.

## v0.0.18

- Studio can be taken to an app with a request to build: the hosted editor bridge gains an optional `agentRuns` capability. Studio announces it; a host that answers it may open Studio with `brief: { prompt, kind }`, and Studio puts the request in its chat and runs its agent on it. Studio then reports its agent to that host (`agent-status`: running with the current step, waiting, paused after a network failure, stopped, finished with the summary, failed with the reason), so the host can show the work and hold its own review while the agent writes. Hosts that do not answer it see the bridge exactly as before. `docs/engineering/FORMLOGIC_INTEGRATION.md` describes the wire.
- Studio's agent knows how to write an app's private backend: a project whose manifest has a `server` block gets a guide to its routes, `server/main.logic` handlers, `softn.sql` and numbered migrations, and to calling it from the page, held by a test to what the host runtime does.
- `.sql` is text to every reader (`application/sql`), the PHP single-app host's copy of the registry included: an editor held a private backend's migrations as opaque bytes, so Studio's agent could neither read the schema nor write the next migration.
- In a hosted editor, the migrations a project arrives with have run on its host's database: Studio's agent is refused a change, delete or rename of one (every file the manifest lists, as well as `server/migrations/*.sql`) and told to add the next numbered migration the project does not have yet, which the host then applies; `check_app` reports one the manifest stopped listing, which the host also refuses. (A host refuses to start on a changed migration; the agent used to rewrite `001.sql` and find out only when the host refused the whole version.)
- `check_app` checks an app's private backend the way its host starts it: routes a host serves (exact `/api/` paths; GET, POST, PUT or DELETE; once each), listed migrations that exist, route settings it understands (`transaction` read or write, `authorization` application or anonymous), listed migrations that exist, each listed once, and an entry that loads in the real engine and defines a function for every route; an entry or migration written `./server/…` is read as the host reads it. A host refuses a whole version whose backend does not start; the agent now finds that before it finishes.
- The backend guide gives a host's SQL rules exactly — the functions a query may call and the `json_each`/`json_tree` it may read, what a migration may add (the clock, `printf`, `format`), `execute` for writes with no RETURNING and `query`/`first` for reads, no triggers, views, PRAGMAs or transactions, SQLite not Postgres — held by a test to the host's own lists in full, and `check_app` refuses what a host always refuses in a migration or in a query written as a plain string (a real model's `datetime('now')` in a query, a `SELECT` through `execute`, and a migration the host would not run). The SQL is read as SQLite reads it, strings and comments in one pass, and a column type's size (`VARCHAR(100)`, `DECIMAL(10, 2)`) is not taken for a call.
- A hosted editor waits 630 s for an AI answer rather than 180: one round of an agent writing whole files runs minutes on a local model.
- A host names its own save button: `open` may carry `saveLabel` ("Save changes"), and Studio's and the Builder's buttons that save back to the host use it, so a person no longer sees "Review changes" in the editor beside the host's "Save changes" for the same action. Hosted, Studio's phone menu has one item for it rather than two (its Run and Publish both returned the draft), and the Builder's hosted data page points to where a hosted app's records now are.
- The hosted editor reads the app a host sends by its type tag rather than `instanceof`, so an array cloned from another realm is not refused.

## v0.0.17

- The FormLogic runtime archive carries the native runtime's `sql.mjs`. v0.0.16's native runtime imported it from `migrations.mjs` and `wasm-host.mjs` but the archive's fixed module list never gained it, so FormLogic's native runtime could not start and every native app request failed. ## v0.0.16

- ZIPP v0.0.21 (commit `9df6e2fd`): the browser engine (`npm run fetch:zipp`) and the Rust host's `zipp-vm` tag move together to the release; the Rust host builds and passes unchanged. ZIPP's Python now parses with its own front end (`zipp-pyparse`) instead of a RustPython fork, runs faster, and prints CPython's tracebacks; Softn's Python and FormLogic dialect suites pass on it unchanged. Since 0.0.21 ZIPP's complete `web-python` bundle builds torch in (9.4 MB raw); Softn takes the new `web-python-base` bundle instead, the same JavaScript-and-Python engine without torch and with a byte-identical glue: 7.46 MB raw (8.2 MB for 0.0.19's engine), so every page downloads less than before and the Workbox precache caps of the web runtime, Builder and Studio stay at 8 MiB. Torch comes from the release's `web-torch` bundle, installed beside the engine as a verified package (`packages/@softn/core/wasm-zipp-torch/`: `zipp_torch.wasm`, 2.05 MB, and ZIPP's `zipp_torch.js` loader), held to the same `SHA256SUMS`, its own, a `BUILD-INFO.txt` pairing it with exactly the installed engine bundle and commit, and proven at install by adding it to the engine and running `import torch`; `wasm-zipp/SOURCE.json` records it under `packages.torch`. The runtime loads it on demand, once per page, only for an app that declares torch; it is not in any PWA's startup precache.
- The JavaScript-only `web` variant is held to import nothing the engine's glue does not provide, rather than exactly the engine's imports: 0.0.21's `web` build has no torch and so does not import the torch kernel hook, which instantiation simply leaves unread. It is still loaded under the engine's glue at install and must report `["javascript"]` with its Python entry points refusing.
- The curated ZIPP notices drop the RustPython parser's MIT licence, since 0.0.21 contains no RustPython code (zipp-pyparse's README says so); the Unicode notice stays.
- A Python app's `.py` files are text in every loader. `@softn/core`'s asset registry had no `py` entry, so a `.py` fell to the opaque-bytes default, the web runtime kept it out of the files the composer reads, and a bundled Python app failed at Run with its own `main.py` "not in the bundle". The Builder's preview, which composes from its own file map, never showed it. The PHP host's copy of the registry gains the same entry.
- Python apps run in every runtime. The shared `processBundle` was typed as three fields of the composition, and the web runtime, the single-app shell and the desktop loader each passed on only those three, so a Python app opened in any of them as a page with no logic at all; only the Builder's preview and the engine tests, which build the prop themselves, ever ran one. Each host now forwards the app's `python` project, and `scripts/python-hosts.test.mjs` fails by name if one stops.
- Python apps can use torch for machine learning by declaring it: `"config": { "python": { "packages": ["torch"] } }` in `manifest.json`. The composer refuses an `import torch` the manifest does not declare, naming the line to add; the inspector refuses a package the runtime does not offer; `torch.py` is a reserved module name; and the runtime adds ZIPP's torch package (`zipp_torch.wasm`, fetched from beside core's chunk, or supplied by a host through `configureZippTorchSource`) the first time a declaring app starts, once per page; an app that declares nothing never fetches it. Only if that load fails is the app refused by name, with the reason, before it compiles. `examples/torch-trainer/` is a working example; `docs/engineering/ZIPP_LANGUAGES.md` has the details.
- Builder: a new project can be JavaScript or Python (`logic/main.py`, a Python starter), `.py` names are kept as typed and held to core's module-name rules, and a new logic file starts with a header in its own language. The logic dock edits the file the active UI file links with `<logic src>`, in that file's language; before, an app without `logic/main.logic` (every Python app) lost dock edits on save, and typing in the Code view inlined the logic so later dock edits never reached preview or export. The Python preview now runs its logic. The file store refuses duplicate paths, which export used to drop silently; `<logic src>` follows moved UI files and renamed folders; the entry file is protected by what the project really runs rather than by two hard-coded ids. Preview is offered while a logic file is open, and canvas images resolve Python string constants.
- Studio: the preview composes through core's `composeBundleSource`, as Run does, so Python logic runs, paths resolve the same way, and a refusal is shown instead of a page with no logic. A brief chooses JavaScript or Python, the scaffold and the model's instructions follow it, and an imported project's language comes from its files. `.py` imports as text, exports under `logic`, and the validator runs the composer before Run or Export. Clicking a page opens it in Studio-created projects, and there is a Python example.
- Security: an `accel` kernel could reach `globalThis` through JSFuck-style syntax the token filter allowed, and so the network without `net`; kernels are now parsed against a small grammar with every name resolved in its scope, and only the rewritten parse reaches `new Function`. `formAction` (and every React-cased URL prop) is judged like `href`; `fallbackSrc` and colour props written into CSS no longer fetch without `net`; QRReader loads its decoder from the host's build instead of jsDelivr; the mic and camera stop after a failed setup; an app is painted inside a contained box so it cannot draw over its consent bar, and markup cannot reach the top layer through `popover`/`commandfor`.
