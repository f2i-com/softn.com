# Engineering audit, September 2026: findings and what changed

An external source review of the runtime, components, applications,
networking, server and site produced eighteen ranked findings on 5 September
2026. This is the record of each one and its status in the tree. The
accompanying design proposal for rooms, authority and portable routing is at
[`rfcs/rooms-and-routing.md`](rfcs/rooms-and-routing.md); it is a proposal,
not an implemented API.

The audit's own framing is worth keeping: the foundation is sound and does
not need a rewrite. Its weakness was consistency — the same identity,
capability and lifecycle rules were applied on some paths and not on their
parallels. Most of what follows is making the parallels agree.

## Implemented

| ID | Finding | Where |
|---|---|---|
| F01 | `<Camera>`, `<Microphone>` and `<QRReader>` gated only on "is the consent bar unanswered?", not on whether the bundle had declared and been granted the device. Any bundle on the shared origin got the camera once one had. | `core/src/loader/consent-gate.tsx` publishes the whole decision per capability; the components ask for the one they need. Video with sound requires `mic` as well as `camera`. Withdrawing a grant stops the tracks. Tests: `components/test/capability-gate.test.tsx`. |
| F02 | A script's `db.startSync` options could name another app's identifier, or a different room from the one it asked for. | `core/src/runtime/host-bound-sync-options.ts`, applied at both entrypoints and — a path the audit did not reach — the worker bridge, which had passed no identity at all and skipped the `sync` permission gate. |
| F03 | The sync registry and the offline CRDT cache were keyed by room label alone, so two apps choosing "lobby" shared an adapter, a cache, and each other's `stopSync`. | `core/src/runtime/xdb-sync.ts`: registry keyed by app and room; cache named by both; status, resume and teardown scoped to the app; a separate `stopAllSync()` for hosts. Tests: `core/test/xdb-sync-scope.test.ts`. |
| F05 | Only `softn.net.fetch` applied the full destination policy. Markup sources, inline styles and the manifest's sync server were held only while consent was pending, then went anywhere. | `core/src/runtime/egress-policy.ts` is the one evaluator; the script runtime, the renderer's URL and style sinks, and the server-sync effect all call it. Remote markup now needs `net` and a permitted host. Tests: `core/test/markup-egress-policy.test.tsx`. |
| F06 | A worker RPC timeout rejected the caller and left the worker running; the app froze with no error. | `core/src/runtime/script-worker-runtime.ts`: a soft timeout for the caller and a hard deadline that terminates the worker, rejects everything outstanding, drops late replies by generation and tells the host, which shows the app as failed. Tests: `core/test/worker-hard-deadline.test.ts`. |
| F07 | The render cache key conflated distinct arguments (`0`/`-0`, `[null]`/`[undefined]`, multi-argument tuples via JSON) and serialised whole object graphs. | `core/src/runtime/sync-cache-key.ts`: lossless primitive keys; reference arguments call through uncached. A helper called twice with the same array in one render now runs twice. |
| F08 | The input throttle could deliver an older pointer sample after a newer one, and dropped wheel notches that shared a frame. | `core/src/runtime/event-coalescer.ts`: per-type policies (latest sample for positions, summed deltas for wheel and pointer-lock movement), delivery in event order, frames cancelled on disposal. Used by both runtimes; `movementX/Y` now cross the bridge. |
| F09 | Stopping sync dropped the adapter but kept its persistence connection and document alive. | `close()` (stop: release the connection, keep the data) and `destroy()` (forget: also clear the stored cache) are now distinct, and `stopSync`/`destroySync` map onto them. |
| F10 | Bootstrap pushed every local record into the loaded document, so a stale offline copy overwrote what the room had agreed on. | Reconciliation by `updated_at` in both directions; a record equal in stamp and content generates no write. Tested with two real Y.Docs. |
| F11 | A batched `refresh` emptied and refilled the whole collection in the CRDT. | Only changed, added or removed records are written. |
| F12 | A collection discovered from the document's `update` event was observed after the transaction that filled it, so its first record was missed. | Discovery projects the map's current contents before subscribing. |
| F13 | A failed WASM initialisation stayed cached for the page. | `core/src/runtime/retryable-single-flight.ts`; the adapter forgets a failed attempt. |
| F14 | `AudioStream` sized its scratch buffer and `AudioBuffer` from whatever a producer returned, outside the VM's memory budget. | Admission before allocation: a block is bounded in seconds, bytes and queue depth, per stream and across the page. Tests: `components/test/audio-stream-admission.test.tsx`. |
| F15 | A failed featured-list request on the home page was swallowed, leaving skeleton cards. | Independent loading, error and retry state in `apps/softn-site/src/pages/HomePage.tsx`. |
| F16 | One failed IndexedDB open disabled the web app cache for the session. | `apps/softn-web/src/lib/appCache.ts` classifies failures: policy refusals stay off, everything else retries after a backoff or on request; `blocking`/`terminated` reopen. Tests: `apps/softn-web/test/appCache.test.ts`. |
| F17 | CI ran only on manual dispatch. | `.github/workflows/build.yml`: typecheck, lint, tests and the web build run on push and pull request; the six-platform desktop matrix stays manual. |
| F18 | Sort controls claimed ARIA tab semantics without the pattern's behaviour. | Plain pressed buttons. |
| — | Homepage: lead with the apps. | `apps/softn-site/src/components/AppShowcase.tsx`: six workloads, launched on request into the existing web runtime, one runtime iframe on the page at a time, device APIs denied in the preview. Copy no longer promises harmlessness. |

A second review of the first pass found gaps in it, closed in the same
series:

- A bundle with no `permission.json` was run with no config at all, which the
  device components and the markup sinks read as "no host is enforcing" — so
  the least-trusted bundles got the camera and remote images unasked. The web
  runtime now runs such a bundle as an empty declaration.
- Signalling servers a script names in `db.startSync` are held to the same
  `net` rules as a fetch; refused ones fall back to the host's defaults.
- Scene3D's `textureUrl` and `modelUrl` are judged by the same policy before
  anything is fetched.
- Two apps that chose the same room label are two rooms on the wire, scoped
  by the stable id the bundle declares (else the host's id for it), because
  y-webrtc keeps one global table of rooms by name.
- The worker's hard deadline measures silence — time since the worker last
  said anything with a request outstanding — so a slow-but-answering worker
  with a queue is never mistaken for a hung one. A killed worker is also torn
  down as a runtime: listeners off, host resources released.
- `camera.modes: ["video"]` is honoured as a complete declaration: video
  records with sound where `mic` is declared and silently where it is not.
  Only an explicit `audio` that the declaration cannot honour is refused.

Compatibility notes for bundle authors:

- Markup that loads a remote image, font or background now needs
  `{ "net": { "enabled": true } }` in `permission.json`, and is held to
  `allowed_hosts` when one is declared. Relative, `data:` and `blob:` sources
  are unaffected. Links (`href`) are unaffected.
- `<Camera mode="video">` records with sound only where `mic` is declared as
  well as `camera`; without it the video is silent. `audio={true}` without a
  `mic` declaration is refused.
- The offline CRDT cache for an app-scoped sync room lives under a new name.
  The room's data is re-derived from the local database and from peers on the
  next connect; nothing is deleted.

## Not implemented

| ID | Finding | Status |
|---|---|---|
| F04 | Texas Hold'em replicates hole cards and the deck through shared game state; any client can read them. | Open. The home page's showcase describes peer play as trusted-peer only; the app itself is unchanged. The fix is a server-authoritative room with public, per-player and authority-only views — the reference design in the RFC — and is a project, not a patch. |
| — | The room API, transport selection, portable named routes and custom-domain mounts. | Proposal only; see the RFC. |

Neither of these is hidden by anything shipped here: the poker app still
works exactly as before, for the people it was written for.
