# Changelog

One section per release tag, newest first. The release workflow takes the
section for the tag being released and puts it at the top of the release
notes, above the downloads table; it refuses to package a tag that has no
section here. Write the section before tagging. Headings are the tag
(`## v1.2.3`); anything after the tag on the heading line is ignored.

## Unreleased

- Size: a production build carries no source maps: the site build, every release and the apps' production builds write none, 27 MB of the site with their compressed copies, read by no visitor (`scripts/build/sourcemaps.mjs`). `npm run build:site:dev` (`--sourcemaps`) builds them for a development deployment, BUILD-INFO.json records which, and `package-site` packages such a build only with `--development`, as `softn-website-<tag>-zipp-<engine>-development.zip`. The packages' own `dist/` keep theirs for development.
- Size: each app's `assets/core-runtime/` holds only what the workers reach (`packages/@softn/core/scripts/worker-files.mjs`): the script, sandbox and local-model workers' modules, the model worker's WebAssembly and licences, and the torch package. It was the whole of core's dist, 4.1 MB of which the workers reach 2.8; core's own `dist/core-runtime/` mirror is the same set.
- Offline: Studio and the Builder are installed whole. Their service workers precache everything they ship, every feature, Three.js and its loaders, the QR decoder and the workers' files included, so an installed editor works offline with every feature, while a page still loads each one only when it draws it. The precache revisions the workers' files, whose names do not change from build to build.
- Offline: an app opened once online in SoftN Web is installed with everything it can reach, so it opens and runs with no connection as an installed app does. The install now also fetches what a component asks for later than its chunk (every Three.js loader, control and effect a `Scene3D` may use, whatever models it is given; a `QRReader`'s decoder), the sandbox worker for an app whose code uses `softn.sandbox`, and for an app that asks for `ai` the AI runtime and the local-model worker, so a model it has loaded before, or one in its own bundle, runs offline. `e2e/tests/offline-app.spec.ts` opens such an app, waits for Offline ready, takes the browser offline and uses all of it.
- A tap before an app's script has loaded is answered once it has. The page is drawn as soon as it is parsed and its functions arrived with the script, so the first tap after opening an app on a slow device, or one right after Allow reloads the script, found no function and did nothing. The renderer hands the page a stand-in for each function the script declares, which waits for the script and calls it.
- A worker-mode app reads a file of its own bundle in the host calls that read one: a model in its bundle (`softn.ai.model.load({bundle})`) said the bundle had no such file.
- A worker-mode app's logic imports are placed as they are on the main thread. A file at the bundle's root importing `./b.logic` asked for `a.logic/b.logic`, a `../` path was passed on unresolved, an indented `import` was left in the code, an import cycle, which the main thread places once, failed the whole load, and logic with no entry path had none of its imports placed. The worker now resolves imports with the main thread's own code (`runtime/logic-imports.ts`).
- Size: Studio, the Builder, the desktop loader and the apps `@softn/vite-plugin` builds load components as the runtimes do, the minimal set with the shell and every other feature (charts, editors, smart views, media and the QR decoder, `Scene3D` with Three.js and its loaders) the first time a page draws it. They imported the whole library, Three.js included, whatever the page used. A Studio preview of a page with a chart fetches the charts and nothing else, and a page without a scene never fetches Three.js; the Builder's entry went from 2.4 MB to 1.1 MB. The three apps share one module for what is fetched on demand (`scripts/build/on-demand-chunks.mjs`). Studio's agent check loads every component a page names before it reads the page, and the Builder's canvas draws a component whose feature is still on its way as its stand-in. `@softn/components/lazy` adds `ensureRuntimeComponents()`, which registers once per registry.
- Size: an app carries the ZIPP engine once. The page compiles its engine, the app's one hashed and precached asset, and posts the compiled module to every worker it starts: the script worker of an app that runs in one, the sandbox behind `softn.sandbox.run` and each local model's worker. Each of them fetched and compiled a second 6 MB copy from `assets/core-runtime/`, which every deployment carried with its compressed copies; it is gone, so softn-web, Studio and Builder are each about 9.7 MB smaller and core's dist 6 MB, an app that runs its script in a worker installs offline without the second download, and a first local model no longer downloads an engine. A host that configures the engine's bytes (`configureZippWasmSource`) has them compiled once for the page and every worker. The FormLogic runtime archive still carries a copy at that path in the hosted runtime and both editors, for FormLogic's release fetcher, which requires one there; nothing reads it.
- Upgrading: a page can now be written as an HTML page is written, and its code kept in `.js` files, with every existing `.ui` and `.logic` app reading as it did (all of the repository's pages and the published demos parse to the same documents as before). Studio makes new projects as `index.html` and `main.js`; a page of your own site can run as the app with no bundle (`softn/softn.js`). The entries below say what changed where.
- HTML in a page. Lower-case tags are HTML, capitalised ones components, mixed freely. `<!DOCTYPE html>`, `<html>`, `<head>` and `<body>` are read through: the head's `<title>` is the document's `title`, and a `<body>` with attributes keeps them on a `<div>`. `<br>`, `<img …>`, `<input …>` and the other void elements end with their tags, where each used to swallow the rest of its parent; a `</br>` is passed over. `<style>` and `<script>` may stand inside an element, and `<Logic>`, `<Style>` and `<Script>` are blocks in any case, where their content was dropped. An `<svg>` draws its paths, shapes, gradients, clip paths and filters, by SVG's names for them, and what they would load from another site goes through the app's network permission. `for`, `readonly`, `tabindex`, `maxlength` and HTML's other attribute names reach React by its names, so `<input readonly>` is read-only. `<input value="…">` and `checked` are a starting value that can be changed; `<textarea>` starts with its text (it drew "[object Object]"); `<pre>` keeps its spacing; an `<option>`'s words reach React as one text; `<my-card>` is one tag name; and every HTML 4 named character reads (`&euro;`, `&eacute;`, `&rsaquo;`), where 33 did. A plain tag loses `is="…"` and any `on…` attribute that is not a handler SoftN made: React writes every attribute of an element it takes for custom, and `is` makes any element one, so `<div is="x" ONCLICK="…">` reached the page as code.
- A page's files, named as HTML names them. `<script src="main.js"></script>` is `<logic src>` and an inline `<script>` a `<logic>` block, in the bundle composer, and `<script src="main.py">` links Python; a `<script>` that is data is passed over, and one from another site is not loaded and says so. `<link rel="stylesheet" href="styles.css">` places a stylesheet the app carries. `<img src="images/logo.png">`, `<video poster>` and `url(images/paper.png)` in a page's styles show the bundle's file, as `asset()` does; they were read against the host page's address. A path the bundle does not carry is left as written. `<a href="about.html">` to another page of the bundle shows that page in the app, composed as its main page and run afresh, its `<title>` the document's, with a history entry so the browser's Back returns; the standalone runtime and softn.com's play pages do this, and a page run with `softn.js` leaves its links to the browser, since each page of a site starts itself. Pages and logic are found by what names them (`main`, `<import from>`, `<script src>`), not by their extension, so a page may be `index.html` and its code `main.js`; the directory and the backend hosts take any name for the main page. Core exports the composer's readers of these references (`pageLogicSources`, `pageStylesheetHrefs`, `logicImportPaths`) for editors to share. A tag inside an HTML comment is commented out: a `<script>` there used to be run, or its file required, and a `<link>` there placed. The runtime's own `softn.js` is no part of the app's code, and a linked stylesheet's `url(…)`s are read from its own folder, as a browser reads them. Several `<script>` blocks on a page are one script, in the order they are written, where the last replaced the others when a page was parsed by itself.
- Handlers and logic written as browser code. `onclick="…"` and the quoted `@click="…"` run their code with the event as `event`, for `oninput` and `onchange` too, and a closing `return false` is `.prevent`; a quoted handler used to be words with a warning. A `<form>` with no `action` keeps its page when submitted, where it reloaded the page and the app with it; one with an `action` still goes there. A logic function handed an event, `onsubmit="send(event)"` or `@input={search}`, gets `target` and `currentTarget` as what those elements hold (`value`, `checked`, `name`, `dataset`) and `defaultPrevented`, and `e.preventDefault()` and `e.stopPropagation()` can be called there and do nothing; the first line of such a handler used to throw. Logic written as a module reads as the script it is: `export` before a declaration is the declaration, and `import { a } from "./b.js"` is `import "./b.js"`; each kept the app from opening. A field with a starting value, `<input value="" oninput="search(event.target.value)">`, can be typed in whatever handles it; one with a handler stayed on its written value. A function named as a handler, `@click={save}`, is given the event's `target` and `currentTarget` on the main thread as in a worker; it was read after the wait for the engine, when React had cleared them.
- A page's code written for a browser is given the page as its document. Code that names `document` gets one, built in JavaScript inside the sandbox and holding the page's own plain HTML from its first line: `getElementById`, `querySelector` and `querySelectorAll` with the selectors pages use, `createElement`, `appendChild`, `remove` and the rest, `textContent`, a real `innerHTML`, `classList`, `style`, `dataset`, `addEventListener` with capture and bubble, a field's `value`, `FormData`, and `DOMContentLoaded` and `load` once the page is drawn. A to-do list written as an HTML page with a `<script>` runs as it does in a browser. What the code changes is drawn through the renderer's one path for elements, so it is checked as markup is: no `<script>`, `<iframe>`, handler attribute or `javascript:` address gets through `innerHTML`. A component, a `{value}`, `#if` and `#each` stay SoftN's: the code can find, move and remove them, not change what is inside; an event inside one reaches the code with its real target, so `e.target.closest('li').dataset.id` on a list SoftN draws works. The code and the markup share state: `{count}` follows a `count++` in a listener. Layout reads (`offsetWidth`, `getBoundingClientRect`) are zero, and Python and code in a worker are not given the document. The rest of a browser's window comes with it: `fetch` as a promise (the hosts it may reach are those the app's `permission.json` allows `net`), `location` (`location.href = "about.html"` goes to another page of the app, never to another site), `URLSearchParams`, `structuredClone`, `queueMicrotask`, `requestAnimationFrame`, `sessionStorage` and `alert()` (`confirm()` and `prompt()` say to ask on the page instead: nothing in the sandbox can wait for an answer); `document.title` names the tab in the standalone runtime; and `onclick="…"` in HTML the code writes runs as a browser runs it. A page whose code names none of these compiles and draws exactly as before.
- Studio makes a new project as `index.html`, `pages/<slug>.html` and `main.js` (or `main.py`), with `<script src>` and `.html` imports, and its AI agent is taught that layout, HTML in a page and `.js` logic. A project made before (`ui/*.ui`, `logic/*.logic`) opens, previews, checks and exports as it did. Studio previews an `.html` page with the runtime, as it does a `.ui` one; an `.html` under `assets/` is still shown as a file. Its check no longer reports `<img src="assets/…">` on an HTML element, which now shows the file. The directory's source view shows `.py` files, and the editors highlight an `.html` page as a page. Its export files a `.js` as logic only when a page links it or logic imports it (a library, a service worker or `softn.js` kept beside the app is an asset), and keeps a file the manifest lists under `assets` there. A link in the preview to another page of the project shows that page, where it took Studio itself to that address.
- The Builder opens a project written as HTML (`index.html` linked to `main.js`) on its main page with that file active (it looked for `ui/main.ui` and left none active), offers the page's functions as it does for `<logic src>`, and writes `<script src>` and the `.html` imports back as it found them. Its own new projects are still `ui/main.ui` and `logic/main.logic`, as is FormLogic's project adapter. Its file tree lists the files at the project's root, `index.html` and `main.js` among them, and renaming or moving a file follows `<script src>` and `<link href>` as it follows `<logic src>`.
- A page of your own site can be the app with no bundle: put the standalone runtime's folder beside it and write `<script src="softn/softn.js"></script>` first in its head. `softn.js` keeps the rest of the document from being drawn or run and loads `softn-page.js`, which fetches the page and what it names (its code and what that imports, its stylesheets, the pages it imports, seed data, and a `manifest.json` and `permission.json` when the site has them, the manifest listing any Python modules) and runs it as the standalone runtime runs a bundle; `data-page` runs another page in its place. Checked in Chromium, Firefox and WebKit. An image's path is read from the page that runs the app, where `data-page` names another, and a host that answers a file it does not have with its index page (an app host's fallback) is taken to have no such file.
- The theme writes its side as `color-scheme` beside its colours on the document. On the standalone page, which stamps no `data-theme`, the brand tokens' dark default stayed, and a light app's text fields, checkboxes and select menus were drawn dark on its white page.
- Components, as a person meets them. A date with no time (`2024-03-15`) in SmartGrid, SmartView and SmartTimeline is the day it names west of UTC, where it showed the day before, and the timeline adds no hour to it. SmartForm sends with an optional number with a `min` left empty, and keeps what is typed when its `data` is written inline (`data={{ status: 'new' }}`), which it put back at every keystroke. SmartStats draws a `trend` given as a number. A Table with `onRowClick` leaves Enter and Space on a button or field in a row to that control. Focus goes back to what opened a Confirm, or a Modal whose content takes focus, where it went to the page's body. A bound ColorPicker takes a six-digit colour typed into it (a three-digit one is taken when the field is left), and the first Escape in a CodeEditor in a dialog is the editor's, as its hint says, where it closed the dialog.
- More components, as review's probes met them. A DataGrid keeps its own filters when the page does not pass them back (they could not be typed in), and an editable column with no `editor` of its own gets a text field. The tab trap in a Modal or Drawer counts a group of radios as one stop. Tabs and a TreeView with `defaultExpandAll` take data that arrives after they are drawn. A dismissed Alert comes back when its words change, an Avatar tries a new `src` after one failed, a DPad hidden while a direction is held releases it, and a Split first drawn where it has no room measures itself once it has. SmartForm takes `defaults` for a new record. NavItem's `page` and `navigate` do what they say, where both were attributes nothing read: `page="about"` shows that page (it sets the app's `currentPage`, or `page` as Studio's projects keep it, and the item is drawn as the current one while its page shows), and `navigate="about.html"` is a link, shown in the app where the host shows that page itself and the browser's otherwise; an address that would run code is no link.
- `$:` values written over several lines are read as the engine reads them: `$: visible = todos` with `.filter(…)` on the next line was cut at the first line, and every recompute gave the whole list. Keys an app captures are its own: one app closing no longer releases another's.
- Records kept in step with a server. An edit made offline survives reconnecting: what the server sends no longer overwrites an edit it has not answered, where the edit was undone and the next one sent the old value back. A record removed for good (`hardDelete`, `db.prune`, `db.clearCollection`) is deleted on the server too, where the next pull brought it back. One server write that failed no longer stops this device's edits from being sent. A script in a worker reads the app's records, where it saw an empty database, and keeps what it wrote. On the desktop a record updated and deleted in the same moment stays deleted, `useCollection` drops a record another device deleted, and the kept copy of a damaged collection is not copied again on every write.
- Directory API: the address a bundle is cached under carries its digest (`bundle.softn?v=N&sha256=…`, on the play page and each version's link), is answered with those bytes or a 404, and is the only one held for a day; `?v=N` alone is revalidated, so a demo the seeder rewrote, or a name purged and published again, no longer leaves the play page refusing the app for a day. A new version that fails before it is recorded leaves no bundle and no trust behind. A publish naming a parent, a remix and a new version check their bundle before taking the catalogue's lock, and a new version is counted against its limit first. The seeder no longer republishes and retires a demo on every request when a folder by its name holds no readable bundle, and a storage collection, record id, key or field with a line break after it is refused.
- XDB is part of SoftN. The Rust crate the desktop runtime and the Rust host store records with is `crates/softn-xdb` in this repository (taken from xdb.org at f76727f, the commit SoftN pinned), its documents are under `docs/engineering/xdb/`, and CI runs its tests. Nothing fetches the xdb.org repository any more. The XDB names in SoftN's API (`.xdb` files, `xdb/` folders, `getXDB`, the desktop commands) are unchanged. A source build of v0.0.24 or an earlier tag still fetches its pinned xdb.org commit.
- Upgrading: an app's style block now styles the app and nothing else. What each rule styles must be inside the element the app is drawn in (`data-softn-app`), while what is around it may be anything, so `.softn-theme-dark .x` still answers to a theme the host sets around the app; `html`, `body` and `:root` are that app's own root as well, so a page's `body { margin: 0 }` and `:root { --brand: … }` mean what they meant. A rule that styled something of the host's no longer does. The app's `@font-face` and `@keyframes` names are its own (an inline `font-family` or `animation` using one follows), and `@import`, `@property`, `@scope`, `@page`, `@view-transition` and at-rules SoftN does not know are dropped.
- Apps are kept to their own part of the page. A bundle's CSS reached the host's whole document: it could hide the permission bar, reword it, set it in a look-alike font, or undo the box the host keeps the app's paint in. The scoping above is read back by the browser's own CSS parser, which removes anything that would still reach outside the app (tested with a corpus of sheets written to make a parser and the browser disagree, in Chromium, Firefox and WebKit: `e2e/tests/app-isolation.spec.ts`). `image-set(var(--u))`, and any image function filled from a custom property or attribute, is treated as loading something unknown: it fetched whatever `--u` held whether or not the bundle had `net`. The desktop runtime and Studio's preview now keep an app's paint in its box, as the web runtime does, so a `position: fixed` element cannot cover the permission bar or Studio (the standalone runtime's page layout does while the bar is asking). An app's `window.addEventListener('keydown', …)` hears the keys aimed at the app, at the page when nothing has focus, and the pointer while the app is on screen: it heard every key pressed in the document, in the host's own fields and in another app's password field, with no permission and while the bar was still asking. `softn.input.captureKeys` holds back only keys the app hears, at most 32 of them.
- Upgrading: `softn.net.fetch` sends no cookie and no referring address of the page an app is drawn in (`credentials: 'omit'`, `referrerPolicy: 'no-referrer'`); an app that signs in sends its own `Authorization` header, as every app in use does, or asks the host's backend (`softn.backend`). `net` with no `allowed_hosts` no longer reaches this computer or its local network (`localhost`, `127.0.0.1`, `192.168.…`, `10.…`, link-local, `.local`, `.internal`, `.home.arpa`): name such a host in `allowed_hosts`, as the apps that use one already do. That holds for every request the runtime judges, markup included, and in the desktop runtime, which also resolves a name and sends the request only to the addresses it checked. `alert()` is shown inside the app, not as the browser's dialog, and `softn.files.saveFile` saves only from a click or a key press.
- More of what an app is kept from. `alert()` used the browser's own dialog, which says the host is speaking ("softn.com says…") and holds the whole tab: an app could word a host's request for a password, or raise one on a timer so nobody could reach the permission bar or leave. It is now drawn in the app, as the app's, never while the permission bar is asking, and at most 50 times. A model or image the `ai` capability downloads needs `net` too, goes with no cookie, follows no redirect, and a relative address (the host's own server) is refused; with `ai` alone, a model URL was a request to any https host. Each app may keep 1 MB in `localStorage` and 3 MB of records in the browser's storage: one bundle with no permissions filled the store the host and every app share, and every write after it failed (an app that already holds more may still write less, and so can always make room). A script's `window.__…` names are not written to the page's window where the host, its frameworks or SoftN may use them (`__TAURI__` written from an app took the page for the desktop runtime, and every app opened after it lost its storage), and the desktop check now asks for Tauri's own bridge. `ping`, `attributionsrc` and SVG's `xml:base` are dropped from markup (each is a request the browser makes by itself, and `ping="/a https://…"` beaconed past the check), and so is an `id` or `name` starting `__`. A component's other style objects (`tooltipStyle`, `overlayStyle`) are judged as `style` is; a Popover's `placement` must be one of its four, a Spinner's `thickness` a number and a Switch's colours colours, since each was written into CSS where any other text loaded an image or added a rule for the whole page. A file an app saves is offered under a plain name: no right-to-left overrides or other invisible characters, no Windows device names, and a kind of file that runs when opened is saved as text. The document shell's marker for its elements can no longer be guessed by the app's markup.
- HTML's boolean attributes are on when they are there, whatever they say, as in a browser: `<input disabled="">`, `<p hidden="">` and `<details open="">` were drawn as if the attribute were absent, since React reads the empty string as no. That is what a page's script writes, so `el.hidden = true`, `button.disabled = true`, `toggleAttribute('hidden')` and `details.open = true` did nothing on the page.
- A second lock behind SoftN's own checks: the site, the web runtime, Studio, the Builder and the standalone runtime are built with a Content-Security-Policy (`scripts/build/script-policy.mjs`) under which nothing runs as script but the deployment's own files, its inline scripts by hash, and WebAssembly; no plug-ins, and no `<base>` that moves the page's addresses. If one of SoftN's checks ever let an `onerror`, a `javascript:` address or a `<script>` through, the browser would still run none of it. It says nothing about what an app may fetch, so it costs an app nothing. The AI capability's engine files now come from the site itself, as the speech worker's do, not from a CDN. (Hashes are taken of a script as the browser reads it, with its line endings made LF, so a build on Windows does not refuse its own.)
- More of what a browser gives a page's code. Forms check themselves as a browser does (`checkValidity()`, `reportValidity()`, `validity`, `validationMessage`, `setCustomValidity()`, from `required`, `type`, `pattern`, `minlength`, `maxlength`, `min`, `max` and `step`), and `requestSubmit()` sends only a valid one; `form.email` and `form.elements.email` find a field; `FormData`, `Headers` and `URLSearchParams` can be listed (`Object.fromEntries`, `for…of`), and a `<select multiple>` gives every choice. `URL`, `btoa`/`atob`, `TextEncoder`/`TextDecoder`, `crypto.randomUUID()` and `crypto.getRandomValues()` (ChaCha20 keyed by the host's own random bytes: numbers a page can rely on), `AbortController`, `EventTarget`, `DOMException`, `MutationObserver`, `IntersectionObserver`, `ResizeObserver`, `matchMedia()`, `innerWidth`/`innerHeight`, and `history` with `popstate` and `hashchange` (within the page; the host's address is not changed). `structuredClone` copies dates, maps, sets and values that hold themselves. Layout is measured once asked for: an element's first `offsetWidth` is zero, and from then on it is its size on the page. `<template>` is never drawn and its `content` can be copied; `<dialog>` has `show()`, `showModal()` (drawn over the app inside its box, not in the browser's top layer), `close()`, `returnValue`, `<form method="dialog">` and Escape; a `<details>` the person opens is open to the code. `NodeList.item()`, iterating a `classList`, `Object.keys(el.dataset)`, whole `a.href` and `img.src`, `<output>`'s `value` and a date field's `valueAsDate`. What the code puts on `document.body` or `document.documentElement` (a theme class, a CSS variable) is drawn on the app's root, checked as any element's attributes are. `fetch("data.json")` reads the app's own file, with no network, as an image of its is read.
- A page written for a browser behaves as one in two more ways: a script that throws as it starts stops there, and the page stays drawn with a note of why (it was replaced by an error); and a handler in its markup that SoftN does not read (`onclick="this.classList.toggle('on')"`) runs as a browser runs it, with `this` and `event`, on a page with code of its own or none, where it did nothing. A backslash in a quoted attribute of an HTML element is a backslash: `pattern="[A-Z]{3}-\d{3}"` asked for the letter d. An HTML element whose end tag may be left out ends where HTML ends it: an `<li>` at the next `<li>` or the list's end, a `<p>` at a `<div>`, a cell at the next cell or row; an unclosed `<li>` held the rest of the page. Pointer events carry `pointerId`, `pointerType` and pressure, and a drag's `dataTransfer` holds what `dragstart` put in it until the drop. (Parser version 10; every repository page and published demo reads as it did.)
- A page is read as HTML5 reads it, and SoftN's own syntax in any case. `<DIV CLASS=card>`, `<BR>`, `ONCLICK="…"` and `</DIV>` are HTML's, values may be unquoted (`src=images/logo.png`), `<textarea>` and `<title>` hold text, an SVG's CDATA is its text, and `&amp` and `&copy` read without their semicolons. `#IF`, `#Else If`, `#EACH (item IN items)`, `<IMPORT … FROM>`, `@CLICK.PREVENT` and `:BIND` are SoftN's, and `<datatable>` is `DataTable` where no HTML element has the name. Misnested markup is built as a browser builds it, by HTML's list of active formatting elements and its adoption agency: `<b><i>x</b>y</i>` opens the `<i>` again after the `<b>`, `<b><div>a</b>c</div>` moves the div out of the `<b>` and leaves `c` unformatted in it (inside copies of any formatting elements between), an `<em>` a `</ul>` closed is opened again around the text after the list, a link ends at the next link, an end tag stops at a block or a table it may not reach through, an `<svg>` or `<math>` ends at a `<p>` or a `<div>`, a table moves what has no place in it to before it and ends at a table written in it, a ruby's annotation ends a paragraph left open in it, and the implied `<tbody>` and a row around stray cells are added. A differential test held 58,000 random fragments to Chromium's own parser with no difference but SoftN's deliberate ones: `/>` ends any tag, a form inside a form is kept, a form written in a table holds its rows, `</form>` closes what is open in the form, and space alone between tags (a page's layout) does not open a formatting element again, where HTML opens it around the space and puts every later block inside it. - Rust backend host, sync: a `create` the client sends again (it re-sends every op until acknowledged, and an acknowledgement can be lost after the commit) no longer replaces the record with its first payload. It wrote over whatever another client had changed since and brought a deleted record back; it is now acknowledged without being written, broadcast or handed to the after-sync hooks. A per-op `onBeforeSync` that returns `{ data: undefined }` keeps the record's payload instead of replacing it with JSON null, as the batch hook already did, and what an after-sync hook throws is logged rather than discarded.

- PHP backend host: `config.server.requestsPerMinute` is read (it was 120 whatever the manifest said; 0 turns the limit off); the lock wait is set before the switch to WAL, so a request opening the database while another closes it waits instead of answering `database_busy` at once; `softn.time.age(date)` without a zone is UTC rather than a 500; the runner's deadline ends the process with a signal, since an exit waited for a worker inside a statement that never finishes and the process outlived the deadline holding its slot and the write lock; the slot lock is not inherited by the runner; and `setup.php` on an archive with no app installed says so instead of dying with a TypeError.
- PHP backend host: a client past its rate limit is refused before anything is started. The runner counted, so a 429 cost a worker slot, a Node process and (on a photo route) the decode, as much as the request it refused, and a client over its limit could keep every slot busy. The runner now notes a refused bucket in `private/limited/` and PHP answers the rest of that minute's requests from it alone, with `Retry-After`.

The limit of eight abandoned workers was a count for the life of the process, and past it a wedged worker was dropped from the pool with no replacement, down to none.
