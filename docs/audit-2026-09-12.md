# Softn audit — 12 September 2026

This audit follows creating, editing, saving, exporting and running an app through
AI Studio, Builder and the browser runtime. It includes the shared renderer,
components and XDB data layer, plus the public landing page. Findings below were
reproduced and fixed; this is not a claim that every possible defect is excluded.

## AI Studio

- **Stop and timeouts cover the complete response.** Previously the timeout and
  abort listener were removed after HTTP headers arrived. A stalled response body
  could hang generation indefinitely. Cancellation now remains active through
  body download, including failed HTTP responses.
- **Partial AI work stays visible and undoable.** A turn can commit edits and then
  request another round. Failure or cancellation in that later round previously
  left the edits without their dirty state and undo card. Completed rounds now
  record their progress and transaction; error messages explain retained changes.
- **Provider choices are explicit.** Missing selections no longer fall back to a
  different provider. Setup validates the endpoint, credentials and required model
  before saving, and the model override explains which requests it controls.
- **Setup works on small screens.** The mobile setup action opens Settings, chat
  drafts survive panel navigation, and settings have larger controls, associated
  labels and visible validation errors. Old error timers cannot clear a newer
  failure, and provider errors containing the word “abort” are not discarded.

Primary code: `apps/softn-studio/src/lib/aiProvider.ts`,
`agentOrchestrator.ts`, `components/panels/SettingsPanel.tsx`, and
`components/ai/AIChat.tsx`.

## Builder

- **Linked projects open under React StrictMode.** Startup effects previously
  consumed `?open=` and then aborted its fetch during cleanup. The replayed effect
  had no link left to load. Startup work now survives that development lifecycle.
- **Edits reach the saved project.** Source, canvas, logic, file-structure and
  undo/redo changes consistently mark the project dirty. Navigation warns about
  unsaved work. Code edits synchronize with the canvas without overwriting the
  authored source, including empty files and source-only comments.
- **Export preserves single-file projects too.** Clearing the only UI file or
  retaining comments no longer falls through the legacy generator after the last
  logic file is removed. Save preparation failures are reported and do not mark
  unsaved work as saved. Oversized files are rejected before allocation.
- **Preview and app logic share their data.** Previously seeded records could
  appear in the preview while `db.query()` returned an empty collection. Preview
  now registers one ephemeral database for scripts, bindings and components,
  seeds it before initialization and uses current Data edits. Each preview is
  isolated from persisted browser and native databases. Closing or replacing the
  preview disposes its data and registry entry; preview interaction does not
  modify the seed records exported with the project.
- **Small screens have useful actions.** Users can open, preview and save a
  project on a phone. Canvas, schema and code editing still require a viewport
  at least 900 CSS pixels wide. Preview controls follow the active theme.

Primary code: `apps/softn-builder/src/hooks/`, `stores/`,
`utils/buildProjectBundle.ts`, `utils/saveProject.ts`, and
`components/preview/PreviewRuntime.tsx` / `LivePreview.tsx`.

## Runtime and data

- **Bundle state belongs to its app.** Changing a bundle or app identity clears
  component state. Disposal is terminal, including hydration that finishes after
  closing; a closed bundle cannot seed data or recreate released resources.
- **Text assets use UTF-8.** Data URLs previously encoded some Latin-1 text as raw
  bytes. Accented and other non-ASCII text now round-trips consistently.
- **Refreshes cannot paint stale results.** Data reads reject out-of-order results
  within one source as well as results from an old source. Successful refreshes
  clear earlier errors. Single-record bindings respond to bulk refresh and sync.
- **Scoped mutations persist and propagate.** Collection-specific native edits
  and deletes reach the native bridge and notify synchronization listeners.
  SmartForm uses collection-scoped edits, awaits desktop saves, prevents duplicate
  submission and displays failures. A save completing after the form moves to a
  different record cannot change the new form. Required checkboxes are validated.
- **File opening gives actionable feedback.** All runtime file entry points share
  one reader. Extension checks accept `.SOFTN`, the ZIP size cap is checked before
  reading, stale selections cannot open after a newer one, and read failures are
  visible. Text drags and app upload controls are no longer hijacked by the shell.
- **Saved data is protected while an app runs.** Home keeps apps mounted. Import,
  bring-forward and removal now reject changes to a running target, with guidance
  to stop it first. Import checks again after asynchronous file reading. Removing
  a stopped app explicitly confirms that its saved data will also be deleted.

Primary code: `packages/@softn/core/src/bundle/runtime.tsx`,
`loader/SoftNRenderer.tsx`, `runtime/xdb.ts`,
`packages/@softn/components/src/smart/SmartForm.tsx`, and
`apps/softn-web/src/App.tsx`, `lib/localBundle.ts`, `lib/useLocalBundleFile.ts`.

## Landing page and working example

The landing page introduces creation, visual editing and running an app before
the directory. It has clearer calls to action, theme-aware spacing, keyboard
operable screenshot tabs, full-size image links and a useful empty-directory
state. The copy accurately describes bringing an AI provider and downloading
source, with corresponding page metadata.

[Fieldnotes](../examples/fieldnotes/README.md) is an editable teaching app created
for the page. Its form validates and saves a task; the list and totals update;
tasks can be completed, reopened and filtered. The runtime keeps records across
reloads. All example records are fictional. Visitors can run the app, open the
same bundle in Builder or download it. The source and deterministic bundle
builder are in `examples/fieldnotes/`.

The walkthrough distinguishes the interface (`ui/main.ui`), the record operations
(`logic/main.logic`) and the `tasks` collection. The screenshots show the real app
inside Builder, not an illustrated mock-up.

## Follow-up refinements — Runtime integration and everyday workflows

The next pass restored app discovery inside Runtime. Its new **Explore apps**
shelf reads the same directory API as the site, and opens apps alongside those
already running. Home keeps the current apps available; opening the same app
again returns to it. Details, Studio, Builder and publishing are linked from the
workspace. The shelf distinguishes loading, an empty directory and a failed
request, with a retry that leaves saved apps usable. Mobile controls have larger
targets and the app menu supports keyboard navigation. Clipboard and fullscreen
failures are visible; the permission dialog's Allow button works in both themes.

The local directory was also empty because the development seeder checked the
wrong parent directory. Correcting that lookup makes the fetched examples appear
in the site's directory and Runtime. The `seedDemos` setting is still respected,
and a built deployment inside a checkout cannot borrow the developer's bundles.
Three regressions exercise those cases with real PHP and disposable folders.

Builder now handles Save while focus is inside Monaco. One pending save owns the
file picker, so repeated clicks cannot start overlapping saves; desktop and
phone controls show the same pending state and recover after a failure. View
shortcuts use the same canvas-flush path as the toolbar. New App and Shortcuts
dialogs have focus containment, Escape dismissal and focus restoration, and the
creation form supports Enter without losing the selected template.

Studio invalidates prepared Run/Publish links when the project or files change,
guards duplicate preparations and shows recoverable failures on desktop and
phone. Recent-project opening claims ownership before awaiting the current
project's save, so a delayed selection cannot replace newer work. Import failures
and progress appear on the dashboard; uppercase bundle extensions work and the
size limit is checked before reading. Its shared local development URL now sends
Publish to the site's origin, where the staged bundle can actually be received.

Site section links now scroll and focus their destination after navigation.
The source reader retries failed requests, ignores superseded versions and offers
a phone file selector, line wrapping and exact-source copying with failure
feedback. It distinguishes empty files from unavailable previews. App pages
isolate ratings and pending work when the route changes; a slow initial rating
read cannot replace a newly submitted vote. Temporary detail failures can be
retried in place. The duplicated pre-publish report has been removed.

## Local development cache recovery

The user's existing browser tab reproduced a problem missed by clean browser
profiles: an earlier production service worker still served its cached Runtime
shell. Its update URL returned Vite's HTML fallback instead of JavaScript, so it
could not update. The network served current source, while the tab loaded an old
hashed entry script and the previous launcher.

All four development Vite configurations now serve a retiring worker at known
Softn worker URLs. It takes over with no fetch handler and unregisters itself;
the next reload reaches current source. It does not delete cached bundles,
IndexedDB records or preferences, or force navigation in other open tabs.
Production build configurations exclude the development plugin.

The existing user tab was refreshed and verified to show **Your app workspace**
and **Explore apps**, with all three saved apps still listed. Seven focused
worker/asset tests and repository TypeScript passed. The real-browser regressions
reproduce both root-scoped and `/web/` stale workers and verify that stored app
records, bundle cache contents and preferences survive recovery. Run
`npm run test:dev-cache` after `npm run e2e:install` to repeat the three cache
recovery checks. Resolving all four production Vite configurations also confirmed
that the development retirement plugin is absent.
